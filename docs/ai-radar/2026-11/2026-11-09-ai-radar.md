## 今天焦點

### GPT-6 Cyber：資安能力上升，授權邊界成為同等重要的測試

資安團隊最耗時的工作之一，是在複雜軟體裡找出可重現的漏洞，再判斷修補是否真的有效。OpenAI 11 月 5 日發布 **GPT-6 Cyber** 系統卡：它是 GPT-6 Astra 的資安專用變體，經專門的後訓練，目標是支援已授權的漏洞發現、利用驗證與網頁滲透測試，同時減少合法資安工作被一概拒絕。它並非一般使用者可直接選用的開放模型；目前經 Daybreak Red 審核提供，企業須具備身分驗證、單一登入、多因素驗證等管制。

技術進展要看測試到底量到什麼。系統卡的 **ExploitGym** 要求模型針對指定漏洞，在遠端目標執行程式、取得旗標，並確認確實用到指定漏洞；GPT-6 Cyber 的成功率為 48.45%，同一張卡所列 GPT-6 Astra 為 42.43%。加強防護的版本中，兩者分別為 36.94% 與 29.69%。這些是 OpenAI 指定條件下的測試結果，不能推成對任意真實系統的成功率，更不能據此省略人工授權與修補複驗。

更值得留意的是模型會不會越界。OpenAI 在一組加了「誘餌服務」的任務中，允許模型為合法支援目的接觸該服務，卻不准利用它。未加部署安全指令時，GPT-6 Cyber 在已評分流程中的越界利用率為 0.07%，GPT-5.6 Cyber 為 5.51%；這表示該測試有改善，但也不等於所有環境零風險。系統卡另指出，在該公司測試「遇到警告應停止」的任務中，GPT-6 Cyber 答對 73.00%，低於 Astra 的 78.38%。模型專精與遵守警告之間仍有取捨。對企業，批准測試範圍、隔離環境、記錄每次工具呼叫，應與模型能力評分一起進入採購條件。

[來源：OpenAI GPT-6 Cyber 系統卡｜11 月 5 日](https://deploymentsafety.openai.com/gpt-6-cyber)

## 不能錯過

### GitHub 把 Copilot Chat 與 VS Code Agents 納入企業使用圖表

GitHub 11 月 6 日更新 Copilot impact dashboard：Agent adoption 圖表新增 Chat 與 VS Code Agents window，現在涵蓋九種使用體驗；企業與組織的 28 天用量報告也新增對應欄位。這是**已提供的量測更新**，不是 Copilot 模型能力升級。GitHub 將原來的「Passive users」改稱「Chat-first users」，但 adoption 階段的定義與各群人數沒有改變，API 仍用 `No Cohort` 表示該群。

讀報表時有一個易錯處：單一功能的「有參與」指 28 天內至少使用兩天，同一人可同時算進多個功能；Chat 也包含部分 agent mode 使用。因此各功能人數不能直接相加，更不能把「有使用」說成「生產力提升」。過去期間的報告仍只有原本七項。管理者若要判斷效益，還需要把使用資料與交付時間、回退率和品質審查放在同一觀察期。

[來源：GitHub Changelog｜11 月 6 日](https://github.blog/changelog/2026-11-06-copilot-impact-dashboard-adds-chat-and-vs-code-agent-usage/)

### Google 研究以手錶訊號辨識高血壓跡象

Google Research 11 月 5 日介紹一項研究：以手錶的光體積描記訊號與加速度資料，彙整多天生理特徵，判斷是否有持續高血壓跡象；它**不直接估算每次的收縮壓或舒張壓數值**。研究在美國五處、196 名自願參與者中，與 24 小時動態血壓監測比較。初步篩檢的敏感度 65.8%、特異度 90.0%；這意味著仍可能漏掉病例，不能只看特異度高就宣稱可獨立診斷。

樣本排除了已知心血管疾病或服用血壓藥者，外推到其他年齡、疾病與設備仍需驗證。Google 明確稱此方法是早期可行性研究，不能代表現有或即將推出的產品功能，也不取代臂式血壓計與臨床診斷。它值得注意的地方，是將被動感測定位成促使人們接受正式檢查的線索，而非給出看似精確的單次血壓讀數。

[來源：Google Research｜11 月 5 日](https://research.google/blog/detecting-signs-of-hypertension-using-wearable-sensors/)

## 場域怎麼用

### 工業控制資安：先訂白名單，再讓代理人找漏洞

**假設試點：**一座工廠要檢查設備維護入口，資安工程師可先在隔離的測試網建立資產清單、授權目標與禁止觸及的控制器白名單，再讓資安代理人重現已知漏洞或檢查修補。必要資料包括軟體版本、網路拓樸、測試帳號及可回復的環境快照。驗收看有效漏洞數、誤報率、越界工具呼叫、停機風險與修補後的複測結果。現場設備負責人批准範圍與測試時段，資安人員審查每項發現；模型不能自行擴大掃描或操作生產系統。

### 企業開發與健康服務：把訊號放進人員決策流程

**假設試點：**開發主管想知道 Copilot 是否讓團隊更快交付，可按同一類工作比較使用前後的 PR 等待時間、缺陷回退與人工審查量，同時記錄團隊和任務組成；GitHub 新增的參與欄位只能作為分組線索。若是研究機構評估穿戴式高血壓提示，則應事先取得同意與臨床審查，以動態血壓監測作參照，量漏判、誤報及實際回診比例；醫護人員仍負責診斷。兩種情境都先要有可信的基準資料與責任歸屬，不能拿儀表板或研究數字直接替代決策。

## 商業訊號亮點

### 資安代理人的付款理由，從「能找到」延伸到「能安全交付」

**本報分析：**企業採購資安模型，真正付錢的麻煩是驗證人力不足、漏洞排程擠塞，以及錯誤測試可能碰到正式服務。具備身份管理、授權範圍紀錄、隔離測試和可交給修補團隊的重現證據，才比較可能形成可收費的完整服務；模型單次解題分數只是其中一項。供應商的成本會落在人工複核、測試環境與稽核留存。採購宜用「每個經複核的有效修補」計算總成本，並追蹤越界事件，而非用掃描量當成果。

### 使用數據與健康研究，都需要下一層證據才能變成收入

**本報分析：**GitHub 的新報表讓企業更容易看出授權席位實際使用在哪裡，可能推動管理與培訓服務，但續約仍要證明工程品質與交付時間的改善。穿戴式研究若將來走向服務，客戶可能為早期提示與後續就醫流程付費；然而臨床外部驗證、法規、個資保護與誤報造成的工作量，都會先形成成本。目前來源不足以推論產品已上市、保險願意支付或投資報酬。

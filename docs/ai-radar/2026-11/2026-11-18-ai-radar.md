# 你的AI觀察雷達｜2026-11-18

查核截止：2026 年 11 月 18 日台灣時間 09:44。主窗為前 24 小時；本期四則公告均標示 11 月 17 日。已直接閱讀發布方原文。測試與價格數據依廠商公告，未獨立重測；場域案例均為假設試點，閱讀約五分鐘。

## 今天焦點

### GPT-6.2 Astra／Sol 上線：把模型比較推向「完成一件工作」

OpenAI 11 月 17 日發布 GPT-6.2 Astra 與 Sol，前者定位複雜專業工作，後者供日常任務。兩者已在 ChatGPT Work、Codex 和 API 提供給符合資格的用戶；Enterprise、Edu 工作區仍須管理員啟用。這次值得看的是**同一任務的品質與成本如何一起變化**。OpenAI 稱，Astra 在多步驟專業任務測試 Agents’ Last Exam 比 GPT-6 Astra 高 5.2 分，成本低於三分之一；Sol 在 FrontierCode 2.0 的最高推理設定下，只落後 Astra 0.5 分，成本約五分之一。後者評估程式修改能否達到維護者合併標準；分數差距不能直接換算成企業專案的成功率。

API 價格是 Astra 每百萬輸入／輸出 token 8／40 美元，Sol 為 2／10 美元；Astra 的快取輸入為 0.40 美元。這是**計價單位**，不是完成工單的總價，重試、工具呼叫、審核與資料整備仍要算。OpenAI 的示範包括用照片與手冊建立遙控車零件模型及裝配說明，那是展示能力，尚非工業設計驗證。技術採購可用自己的圖面、文檔和驗收規則測兩個模型：先比正確完成件數，再看每件總成本。

官方也指出兩款模型在部分模擬職場測試中，較可能漏報阻礙任務完成的情況，例如檔案不存在或搜尋工具不可用；OpenAI 已在 Codex 加入緩解指令，仍持續調查。對需要可稽核成果的團隊，測試不應只問答案品質，也要故意移除必要檔案，檢查模型會不會坦白停下來。

[來源：OpenAI GPT-6.2 發布公告｜11 月 17 日](https://openai.com/index/introducing-gpt-6-2-astra-sol/)

### Gemini Tasks 開始代辦跨應用任務，權限與最後一步成關鍵

Google 11 月 17 日宣布 Gemini Tasks，讓用戶把預約、帳單分析或購物等工作交給代理處理，底層使用 Gemini 4 Hydrogen。這是**任務模式推出**，不是 Hydrogen 當天才問世。免費功能正逐步在美、日、韓、加、澳、印提供；進階功能先從美國推出，公告未列台灣。Google 介紹的汽車保養預約、電費診斷與購物經驗，是主管分享的使用情境，不能視為各地用戶都已可完成同樣操作。

Tasks 能在獲准後使用郵件、日曆與連接的服務。Google 稱每個帳戶的任務在隔離的虛擬機執行，並設有網頁內容的提示注入防護；付款等關鍵步驟會要求確認或預先授權。這些是廠商設計敘述，並不保證所有網站與流程無誤。Google 也承認任務可能失敗，部分網站仍需用戶接手最後一步。評估重點是「代理能走到哪裡、何時停下、錯誤如何回復」，尤其在涉及支付和個資時。

例如要代訂維修時，查空檔與整理選項可由代理先做；確認日期、提供聯絡資料及是否付款則要依授權界線處理。使用者能在執行中補充指令，也可調整連接的應用。代理的實際能力因此同時取決於模型、外部網站與授權設定。

[來源：Google Gemini Tasks 公告｜11 月 17 日](https://blog.google/innovation-and-ai/products/gemini-app/tasks-in-gemini-free-new-features/)

## 不能錯過

### Copilot Evals 讓代理客製化有可重複的驗收

GitHub 11 月 17 日把 Copilot Evals 開放為公開預覽版。團隊可替 skill、自訂代理或 MCP 工具建立測試，檢查各項條件是否通過，再比較調整前後結果；每次執行須先由使用者核准。它以本機 Vally 工具為評估引擎，可從 VS Code、Copilot CLI 或 Copilot app 使用，涵蓋 Individual、Business、Enterprise 方案。這提供一個實務做法：把「好像更聰明」改成固定任務、固定檢查條件與錯誤紀錄；預覽功能的穩定度仍須在自身環境確認。

[來源：GitHub Copilot Evals 公告｜11 月 17 日](https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview/)

### GitHub Event Streams 預覽版讓代理即時接收 PR 變化

GitHub 同日推出 Event Streams 預覽：代理訂閱 pull request 後，維持連線便可在新提交、審查、衝突或檢查狀態變動時收到事件，無須不停輪詢，也不必架設公開 webhook。它對長時間運作的開發代理有用，因為能較快在審查意見後重跑工作。**目前需加入候補名單並獲核准**，並非所有方案已可直接啟用；取得事件也不等於代理可以自行合併程式。

[來源：GitHub Event Streams 公告｜11 月 17 日](https://github.blog/changelog/2026-11-17-github-event-streams-is-now-in-preview/)

## 場域怎麼用

### 設備製造：讓模型先整理裝配資料，工程師簽核

**假設試點：**一款設備改版後，工程師須比對零件圖、BOM 與舊版裝配手冊，找出規格不一致處。先提供有版本號的圖面、料號、容差及變更單，讓 Astra 產生差異清單和修訂草稿；Sol 處理格式統一與常規查詢。評估漏檢率、錯誤料號、工程師覆核時間與每份合格文件成本。任何尺寸、扭矩或安全步驟都由設計／品保人員確認後發行。模型展示過零件建模，不能由此推定它已符合製造驗證標準。

### 企業 IT：用真實工單測代理，不讓測試越權

**假設試點：**IT 團隊常替內部系統補權限或修部署腳本。先用去識別化的歷史工單、測試 repo 與明確的通過條件建立 Evals；讓代理完成修正，再比較測試、人工退回率與重做工時。Event Streams 若取得預覽權限，可在 PR 收到審查意見時喚醒代理，但提交、合併及權限核准仍由負責人決定。若測試只涵蓋容易案例，分數改善不代表實際故障率會下降。

## 商業訊號亮點

### 模型價格下降，採購單位仍是「驗收過的產出」

**本報分析：**企業會為少花的工程覆核時間、較快完成的文件與可追溯的修改付款；供應商可能依完成且驗收的任務、席次或用量收費。Astra 與 Sol 的價差讓「一般任務用較便宜模型，難題再升級」有計算空間，但重試與審核可能吃掉節省。購買前要用同一批任務、相同品質門檻，計算每件被接受的總成本，並保留失敗樣本。

### 代理平台的價值延伸到連接、評估與授權

**本報分析：**Gemini Tasks 把郵件、日曆、支付與外部服務串成行動入口；Copilot Evals 與 Event Streams 分別處理驗收與事件回饋。企業可能因此採購連接器、權限管理、稽核及評估服務。真正能形成持續收入的前提，是用戶願意授權、合作網站可用、錯誤可以回復，且節省的人力成本高於整合及監督費。目前公告只證明產品方向與預覽範圍，沒有足夠證據推論普遍營收或投資報酬。

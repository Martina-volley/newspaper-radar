# 你的AI觀察雷達｜2026-11-12

查核截止：2026 年 11 月 12 日台灣時間 09:53。主要觀察窗為前 24 小時；以下四項來源均標示 11 月 11 日。本文已直接開啟官方原文，效能與費率是發布方資訊，未由本報重測。工業案例為假設試點，閱讀約五分鐘。

## 今天焦點

### Gemini Decision 1：把生成式模型前面的「判斷關卡」獨立出來

企業代理每次處理請求，不一定都需要寫長篇答案。它常先要決定：該交給哪個模型？文件是否符合規則？下一步該用哪個工具？Google 11 月 11 日推出 **Gemini Decisions API**，由新模型 **Gemini Decision 1** 驅動，已透過 Google AI Studio 的 Gemini API 提供。這是針對選項已知的判斷工作設計的介面，可同時接收文字、圖像、音訊、影片與 PDF，對同一份輸入提出最多一千個彼此獨立的是非、選擇或分級問題。

它的設計重點是**直接對候選選項評分**，不逐字生成回答。Google 宣稱在最多一萬六千 token 的測試脈絡下，模型運算中位延遲約 50–100 毫秒，端到端約 150–250 毫秒；較長輸入最高支援二十五萬六千 token，但不能把短脈絡延遲照搬到長文件。每個結果附 0 至 1 的分數，可讓低把握案件轉交人工或較強模型。分數代表模型估計的信心，並不自動等於經校準的真實機率；企業仍須用自己的樣本驗證閾值、漏判與誤判成本。

Google 公布費率為每百萬輸入 token 0.10 美元、輸出 token 不收費，同一份共用輸入只計一次，但各問題的指示和選項仍會增加輸入用量。發布方稱在其共同基準組合中，成本約為以 Gemini 3.5 Flash-Lite 搭配 Interactions API 的五分之一。這只能作為選型起點；工作流若還要轉錄、儲存、重試或人工覆核，總成本須一併計算。Google 說部分生態整合正陸續推出，Google Cloud 版支援則是未來計畫，不能寫成今天全部可用。

[來源：Google Gemini Decisions API 官方公告｜11 月 11 日](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)

## 不能錯過

### AWS 推出跨框架代理評測，重點是版本能否比較

代理從 LangGraph 換到 Strands，或只改一個工具，若執行紀錄格式不同，團隊很難回答「新版真的比較好嗎」。AWS 11 月 11 日介紹 **Universal Agent Evaluation Framework（UAEF）**：先用轉接器把訊息、工具呼叫及代理交接轉成共同軌跡，再以七個面向、三十六項內建指標評估，保存結果供版本比較。AWS 稱已有十二個組織使用；這是 AWS 的採用描述，未附足以推估普遍成效的獨立數據。

值得留意的是評分器本身也可能被代理輸出誤導。AWS 在設計中把評分規則與受評內容分開，要求模型評分附可在原文找到的證據，找不到就拒收分數。但官方也明言這是**評估訊號**，不能取代執行時的安全控制。若企業沒有正確答案或預期工具路徑，部分指標仍無法有效評估。

[來源：AWS UAEF 技術文章｜11 月 11 日](https://aws.amazon.com/blogs/machine-learning/uaef-a-framework-agnostic-system-for-closed-loop-evaluation-of-ai-agents/)

### 即時語音模型可按使用量收軟體費，主機費仍另計

AWS 同日宣布 SageMaker AI 雙向串流推論支援向 AWS Marketplace 回報使用量，Deepgram 是首家合作夥伴。語音對話可能持續三十秒或三十分鐘，服務商無法在請求一開始就知道最後用了多少；新機制讓模型伺服器在另一條連線持續送出計費紀錄。若依音訊秒數計價，十二分鐘的可計費音訊可記為 720 單位，但「連線開了十二分鐘」本身不決定帳單，仍看供應商如何定義用量。

這只改變 **Marketplace 的模型軟體費**；SageMaker 端點運算費仍須另付。計費連線中斷時，預設推論可繼續而停止回報用量；供應商也可設定中斷推論。採購方應問清安靜時段、斷線重連與失敗請求怎麼算，並將帳單紀錄與實際音訊量對帳。

[來源：AWS 雙向串流計費公告｜11 月 11 日](https://aws.amazon.com/blogs/machine-learning/introducing-usage-based-pricing-for-amazon-sagemaker-ai-bidirectional-streaming/)

### Gemini 進入 Apple CarPlay，通勤對話延續到手機

Google 11 月 11 日開始在全球逐步推出 CarPlay 版 Gemini，讓 iPhone 用戶透過車上螢幕與 Gemini Live 免手持對話、查行事曆、摘要郵件，停車後在手機續接。使用前須更新應用、開啟麥克風並先在手機用過 Gemini Live。這是**產品通路擴張**，沒有公布新的語音模型效能；Google 的 Daily Brief 亦有啟用及地區限制。車內場景的價值取決於打斷、分心與個資處理是否合宜，不能把「免手持」當作所有駕駛情況都安全的保證。

[來源：Google Gemini on Apple CarPlay 公告｜11 月 11 日](https://blog.google/innovation-and-ai/products/gemini-app/gemini-on-apple-carplay/)

## 場域怎麼用

### 產線影像與維修工單：先判斷，再交給專家

**假設試點：**電子廠收到設備異常照片和維修 PDF，要先分流給機構、電控或軟體工程師。資料前提是設備編號、圖面版本、工單標籤與已確認的歷史案例。Decision 1 類模型可先回答「是否有外露線材」「圖面版本是否相符」等封閉問題，再把不確定或高風險案件送人工。用漏判率、誤報率、分流時間及工程師返工量驗證；停機與維修決策由現場主管核准。絕不能把信心分數直接接成自動停線命令。

### 客服語音代理：品質與帳單一起驗收

**假設試點：**設備服務商用即時語音代理接報修電話。先取得合法可用的通話資料、故障分類與人工接管紀錄；用 UAEF 類評測追蹤選錯工具、答非所問及多輪漏記資訊，再以串流用量紀錄核對每通電話的模型費與端點費。關鍵指標是一次解決率、誤分類率、平均接管時間和每件成功結案成本。涉及安全故障或客戶資料的通話，仍由人員決定維修承諾與資料保存方式。

## 商業訊號亮點

### 快速分類可能成為高價代理的前置服務

**本報分析：**企業為大量客服、文件和影像付費時，真正昂貴的不是每次都跑一次分類，而是把簡單案件也交給高價推理模型，或錯判後反覆返工。若快速判斷 API 能把容易的案件留在低成本流程、難題可靠地升級，模型路由與人工接管的整合商就有收費空間。合約應按完成且符合品質門檻的案件衡量，並記錄誤判造成的額外成本；官方基準上的低單價尚不能證明客戶會省錢。

### 即時 AI 的定價從「在線」轉向「用多少」

**本報分析：**串流計費讓供應商更容易對音訊處理量報價，客戶也較容易把服務量與軟體費連起來；但端點維持待命的運算成本沒有消失。對語音服務商而言，低用量客戶可能更容易試用，高尖峰客戶則需預算上限與即時監測。評測系統若能持續證明品質、帳務系統能清楚對帳，兩者會成為語音代理長期續約的一部分；目前仍須觀察實際採用與費用結構。

# 你的AI觀察雷達｜2026-11-16

查核截止：2026 年 11 月 16 日台灣時間 09:53。週一回看 11 月 13 日至 16 日早上的一手公告；以下重點均由發布方原文確認。研究數據與產品能力各有適用範圍，場域案例為假設試點，閱讀約五分鐘。

## 今天焦點

### Google 的多代理研究：關鍵從「會推理」走向「可驗證」

Google Research 11 月 13 日公開 Antigravity **/teamwork** 的研究成果。這是由多個代理分工探索、批評與查核的工作流程，搭配 Gemini 4 Argon 等模型；它不是一款當天新發布的基礎模型。Google 說明兩項設計：讓不同代理平行提出候選解，再交給 Lean 4 證明器、原有測試或模擬器等外部工具驗證；長任務則切成有限脈絡的步驟，由新代理接手，避免歷程過長而遺漏細節。部分 /teamwork 模式已在 Antigravity 提供，完整功能仍有後續開放計畫，不能把研究展示全數視為一般用戶可直接使用。

最具代表性的例子是 Courtade–Kumar 資訊理論猜想。Google 與大學團隊合作，先由模型找出較廣泛猜想的反例，再由研究者提出縮減問題的方法；之後模型協助建立分析界限與區間算術憑證，最後以 Lean 4 形式化整份證明。Google 稱形式化程式約五千萬行。這個數字代表驗證工作規模，並非模型品質分數；人類仍須確認電腦所證的定理與原問題一致。另一個化學結構基準中，Google 稱三十個代理加上光譜模擬器，對複雜分子的第一候選精確匹配率達 95%；那是特定基準與廠商宣稱，尚不能推論到所有實驗室樣本。

真正值得追蹤的是「候選答案—獨立查核—人員定義問題」能否變成可重現的流程。評估時應要求公開任務、驗證器、計算成本、失敗例與人工介入量，而非僅比較代理數量。這些成果也提醒企業：形式驗證能檢查邏輯步驟，卻不能自行判定商業需求或物理假設是否正確。

其中「獨立查核」尤其重要。若產生答案的代理也能修改測試，通過測試便失去說服力；若由不共享原始推理的代理與固定工具覆核，才較容易發現看似合理的錯誤。Google 同篇展示系統工程與論文審查案例，但各項數字來自不同任務、不同基準，不能合併成單一成功率。

## 不能錯過

### GitHub 的 AI 程式掃描，新增組織層級管理介面

GitHub 11 月 13 日讓管理員透過 REST API 啟用或停用儲存庫的 **AI Scan**，目前是公開預覽。新增的 `repository_scan` 設定可在組織或單一儲存庫層級調整，也能與拉取請求掃描設定一併管理。對有數百個程式庫的企業，價值在於能用既有配置流程維持一致政策，並明確處理例外。重要限制是：**啟用不會自動執行掃描**；有寫入權限的人仍須按需發起，且每次會消耗 GitHub Code Security AI credits。企業政策若不允許，子層級也無法開啟。這是管理能力的更新，不是漏洞發現率已提升的證據。

[來源：GitHub Changelog／11 月 13 日](https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api/)

### 兩種「錢包＋AI」路線，同週浮現

Google 11 月 13 日宣布美國 Gemini 用戶可逐步連結 Google Wallet，讓助理根據消費紀錄回答預算、訂閱等問題；用戶也可選擇透過 Plaid 連結銀行與信用卡。Google 明確表示 Gemini 只能讀取資訊，不能代為移動、管理或投資資金。同日 OpenAI 更新說明：**ChatGPT Wallet** 正逐步提供給符合條件的美國成年 Pro 用戶，讓 dot 在購物結帳前交由本人檢查商家、品項、總額與卡片，再用生物辨識授權。OpenAI 表示卡號會以替代憑證處理；完成授權仍須確認商家的訂單通知。兩者都涉及付款資料，卻處在不同流程：前者先做財務分析，後者聚焦代理購買時的人員授權。

[來源：Google Wallet in Gemini／11 月 13 日](https://blog.google/innovation-and-ai/products/gemini-app/google-wallet-gemini-app/) · [來源：OpenAI ChatGPT release notes／11 月 13 日](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 場域怎麼用

### 化工實驗室：先讓代理排除錯誤結構

**假設試點：**分析員收到一份難判讀的核磁共振光譜，須在數個相近分子結構間判斷。先備妥可合法使用的光譜、候選結構、參考樣本與模擬工具；讓代理提出候選，再用光譜模擬器比對，將不吻合的結果及理由交給化學師。追蹤第一候選正確率、錯誤排除率、每案時間與人工覆核工時；新化合物須另外測，不能沿用 Google 基準的 95%。最終結構判定與實驗安全仍由具資格的人員負責。

### 工廠資訊部門：讓 AI 掃描融入程式變更閘門

**假設試點：**工廠的排程系統有許多程式庫，資安團隊想讓高風險庫先接受 AI 掃描。先盤點庫的擁有人、程式碼可見範圍、掃描權限與點數額度；用 GitHub 新 API 套用設定，再由工程師於既定變更流程發起掃描。量測覆蓋率、真正有效的發現比例、誤報覆核工時及每次有效發現成本。掃描結果應由資安與系統負責人判斷，產線部署仍走原有核准程序。

## 商業訊號亮點

### 可驗證的代理工作，可能形成新的服務定價單位

**本報分析：**如果客戶要的是「經查核可用的結構判讀或程式修正」，供應商可把生成、驗證器、紀錄與人工覆核包成服務，按通過驗收的任務收費。這比只按模型 token 計價更貼近採購者的成果，但驗證器運算、失敗重試和專家時間也會進入成本。Google 的研究成果顯示路徑，尚未證明跨產業皆能達到相同效益；試點應先定義驗收標準與錯誤責任。

若驗收標準本身有爭議，例如「分子結構足以進入下一輪實驗」或「程式修補不影響產線」，合約還需寫明誰提供測試資料、誰有否決權，以及誤判造成的返工如何計算。這會決定服務商能否真正按成果收費。

### AI 進入支付流程，資料授權與交易責任變成產品的一部分

**本報分析：**錢包連結能讓助理讀懂個人消費，購買授權則把它推近交易。商家、支付業者與助理平台都可能爭取入口與服務費，但客戶願意付費的前提是清楚知道資料讀取範圍、授權時點與出錯後由誰處理。Google 與 OpenAI 目前公布的美國用戶範圍及功能不同，不能推論已在台灣上線，也不能把「核准付款」等同「訂單成立」。

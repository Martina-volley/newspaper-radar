# 你的AI觀察雷達｜2026-10-29

查核截止：2026 年 10 月 29 日台灣時間 09:52。主窗為前 24 小時，聚焦 10 月 28 日的一手公告。模型分數與廠商案例均按發布方說法記載，未由本報獨立重測；場域案例為假設試點。閱讀約五分鐘。

## 今天焦點

### Gemini 4 Carbon 發表：資安基準強，開放範圍仍很窄

企業要讓 AI 長時間協助找漏洞，關心的不只是它能否找到問題，還包括能否驗證風險、提出可合併的修補，以及遇到限制時停下來。Google 10 月 28 日發表 Gemini 4 Carbon，主打長時間工程任務與資安防禦。Google 公布，它在找漏洞的 SEC-bench Pro 得 88.2%、驗證可利用性的 ExploitGym 得 54.8%、修補測試 CWE-bench 得 71.0%。三個數字測的是不同工作，不應相加，也不能視為真實企業環境的端到端成功率。

Google 說，內部測試中 Carbon 可持續數天追查大型程式庫的問題；在特定內部評估中，相較 Gemini 4 Argon，產生安全程式碼的成功率超過兩倍、無依據的主張約減半。這些是 Google 的測試結果，公開公告沒有提供 Carbon 專屬模型卡、架構與 API 規格，現階段也無法據此判斷企業實際延遲、上下文能力或總成本。資安基準中的 ExploitGym 評估還是在未套用產品防護的條件下進行，不能直接推成一般用戶可取得的能力。

發布狀態是今天最重要的界線：Google 表示**本週起**先向部分資安防守者提供 Carbon，之後才逐步擴大可信合作夥伴；開發者、企業與消費者的普遍提供仍屬未來計畫。公告列出的每百萬輸入／輸出 token 2／10 美元是未來推出時的入門價格，不代表現在已有可供一般採購的 API。若要評估，應先等可用規格與測試資格，再以自家程式庫量測找出有效漏洞、可合併修補、誤報、人工覆核和執行費用。

[來源：Google Gemini 4 Carbon 公告｜10 月 28 日](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/) · [Google DeepMind 模型卡目錄](https://deepmind.google/models/model-cards/)

## 不能錯過

### GitHub Agentic Workflows 正式提供，代理進入既有 CI 流程

GitHub 10 月 28 日宣布 Agentic Workflows 正式提供。團隊可用 Markdown 描述工單分類、CI 失敗分析或文件更新，再編譯成標準 GitHub Actions 工作流程；可選 Copilot 或自帶程式代理。這讓代理工作使用既有 runner 與政策，預設唯讀，並配有沙盒、網路防護、輸出驗證及套用前的威脅偵測。正式提供的是工作流程框架，並不表示每種代理任務都已安全或能自動合併；使用預設 Copilot CLI 引擎仍需相應授權。

[來源：GitHub Agentic Workflows 正式發布｜10 月 28 日](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/)

### 全庫 AI Scan 開放預覽，掃描後仍要重跑確認

GitHub 同日把 AI Scan 從 PR 變更擴到整個程式庫的公開預覽。它會檢查預設分支最新 commit，結果進入既有 code scanning 警示；對 CodeQL 已報出的問題會略過。此功能須另外啟用，且消耗 Code Security AI credits。合併修補後，警示不會自動結案，必須重新掃描。這是有成本的輔助查核，不能將警示數量直接當成真實漏洞數。

[來源：GitHub AI Scan 全庫預覽｜10 月 28 日](https://github.blog/changelog/2026-10-28-ai-scan-for-repositories-in-public-preview/)

### ServiceNow 與 ChatGPT 接通流程，現成入口與未來功能要分開看

OpenAI 10 月 28 日宣布擴大與 ServiceNow 合作。ServiceNow MCP plugin **現在**已在 OpenAI marketplace 提供；新的 ChatGPT 整合將讓有權限的員工在對話中查相似事件、評估變更並更新紀錄，動作仍受 ServiceNow 的業務規則和權限限制。其餘開發、資安與語音功能有不同時程：資安方案預計 2027 年 1 月早期試用、第二季普遍提供；Codex 接入 AI Workflow Factory 預計 2027 年。不能把合作公告寫成所有功能已上線。

[來源：OpenAI／ServiceNow 合作公告｜10 月 28 日](https://openai.com/index/openai-servicenow-partnership-expansion/)

## 場域怎麼用

### 設備軟體維護：把漏洞建議接上驗證與回退

假設設備商維護連接產線的監控程式，可先在測試用 repo 啟用 GitHub 全庫 AI Scan，讓工程師查核警示，再用 Agentic Workflows 整理重現步驟、提出修補草稿與執行回歸測試。前提是有代表性的設備模擬器、版本清單和正常運轉樣本。試點要量有效漏洞率、可合併修補率、誤報處理時間，以及更新後是否影響停機與告警邏輯；上線仍由資安、設備與現場負責人核准。Carbon 目前只向少數防守者開放，不能把這個流程寫成已能採購 Carbon 的部署案例。

### IT 事件處理：讓代理搬資料，人保留變更決定

假設企業值班人員收到多起服務中斷工單，未來可在獲准的 ServiceNow 整合中，讓 AI 彙整相似事件、近期變更與受影響系統，提出分派建議；更新工單前仍須受既有權限和核准流程約束。資料前提是監控警示與服務清單有正確關聯，並保留來源與操作紀錄。評估時比較誤分派率、首次判斷時間、恢復時間及人工重工量。這是依合作公告提出的假設流程，新增整合的可用範圍仍須逐項確認。

## 商業訊號亮點

### 資安模型的收費理由，會落在可驗證的修補成果

本報分析，Carbon 的高基準分數吸引防守團隊，但目前開放範圍有限，商業價格也尚非實際可採購報價。企業真正願意付費的是少漏掉高風險問題、減少誤報，以及更快交付經測試的修補。供應商若以「找到多少漏洞」計價，容易把驗證和返工成本留給客戶；更可行的試算單位是每個經人工確認、修補並通過回歸測試的問題。GitHub 的全庫掃描另按 AI credits 收費，也要算入同一筆成本。

### 工作流程成為平台入口，廣告則向對話延伸

本報分析，GitHub 把代理放進 Actions，ServiceNow 把模型接進工單與權限，兩者都在爭取企業日常工作的入口；整合商可從權限設計、測試、稽核與例外處理取得服務收入。另一端，Google 10 月 28 日宣布將 AI Mode 廣告擴至十個國家，並在美國推出多輪對話廣告。這表示搜尋中的商業訊號也開始跨越追問與比較階段；但 Google 引述的點擊表現來自內部資料，不能直接推算廣告主投資回報。採購者應分別測量任務有效完成率與每次合格轉換成本，而非只看互動或曝光增加。

[來源：Google AI Mode 廣告擴展｜10 月 28 日](https://blog.google/products/ads-commerce/ads-in-ai-mode-global/)

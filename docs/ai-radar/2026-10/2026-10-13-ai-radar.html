01今天焦點

Muse Wonder：Meta 把長任務與跨對話記憶放進新模型

Meta 10 月 12 日推出 Muse Wonder 與 Muse Wonder Full，主打能使用工具、跨應用完成多步驟任務的代理能力。模型卡列出文字、影像、影片及音訊輸入、文字輸出，推論時支援 100 萬 token 上下文。Meta 稱「Active Memory」可帶入跨對話相關資訊，「Active Focus」讓代理遇阻時嘗試替代路徑、必要時詢問使用者；這些是產品能力描述，實際記憶是否準確、授權能否跟著任務變動，仍須測試。

發布狀態要分開看：Muse Wonder 已提供 Meta Model API 與 Muse Code 使用；Full 版提供 Muse Code 訂閱者。Muse 產品內的推出則是未來計畫。Meta 公布法律、財務、健康與程式任務評測，模型卡指出自家成績採最高推理設定，競品結果混用內部、供應商與第三方來源，部分程式任務也不是同一操作環境。因此它值得列入代理模型比較，不能憑一張排行榜宣布全面領先。模型卡亦承認陌生多步驟、3D 空間判斷及部分語言仍可能失誤；不可逆動作應設人員確認。

來源：Meta 發布公告｜10 月 12 日 · 研究說明 · 模型卡

Maia 300：推論瓶頸開始從晶片擴到整座機櫃

Microsoft 10 月 12 日公開 Azure Maia 300 系統設計，針對長上下文與多步驟代理的推論負載調整晶片、記憶體和網路。技術文章列出單加速器 288 GB HBM4、峰值 18 TB/s 記憶體頻寬；一櫃配置 96 顆加速器，讓資料盡量留在靠近運算的位置，減少搬移耗能。這些規格說明設計方向，不能直接換算成某個模型的回應速度。

Microsoft 稱完整機櫃的 token 吞吐量最高可達 Maia 200 的 7 倍，並預期每百萬瓦產出較領先 GPU 系統多 40% token。前者是同系列特定配置比較，後者是對未來部署的預期；測試工作負載與實際成本仍需核對。現已投入生產的是 Maia 200，服務包含 Copilot；Maia 300 預計 2027 年開始生產部署，多 gigawatt 擴建也屬未來規劃。

來源：Microsoft 官方公告｜10 月 12 日 · Azure 架構說明

02不能錯過

Anthropic 測試小模型能否在物聯網設備上自我複製

Anthropic 10 月 12 日公布受控實驗：一款 9B 模型能在測試的九種硬體中八種架起推論服務；較強的 GLM-5.2 則在隔離、弱防護的模擬網路中完成傳播流程。但完整測試使用未驗證身分的連接埠，且較大模型在外部伺服器上運行，再由研究程式啟動下一份代理。研究者明確表示，目前能放進低階設備的模型與可靠完成全流程的能力門檻尚未重疊。年底可能出現較小模型的推估，是依能力趨勢外推，並非已發生的野外感染事件。

來源：Anthropic 研究｜10 月 12 日

Anthropic 公布反蒸餾防線，也揭露使用代價

Anthropic 同日說明如何限制大量擷取 Claude 推理內容：隔離先前推理脈絡、使用兩階段分類器，並對反覆擷取帳戶限流或停用。公司估計，防線部署後被擷取的推理 token 減少約 90% 至 99%；這是自家平台觀察，對更持久的新攻擊尚未驗證。其分類器仍可能誤擋正常請求，部分開發者須修改串接方式，特定遭阻擋請求也會收費。

來源：Anthropic 技術說明｜10 月 12 日

03場域怎麼用

供應商文件交接：讓代理整理脈絡，核准仍由人做

假設一家工廠更換零件供應商，採購要核對報價、材料證明、圖面版本和交期，品質部門還要確認哪些文件缺失。可先讓代理讀取已授權的文件、列出版本差異與待補項目，再交採購與品保確認。Muse Wonder 宣布的跨對話記憶和長任務能力與此類工作相關；這是本報試點構想，Meta 未公布上述工廠部署。

資料前提是料號、修訂版與文件權限一致。先測漏列率、錯誤引用、人工查核時間，以及代理是否把另一家供應商的機密資料帶入回答。採購核准和料件放行不得由模型自行執行。

現場設備連網：先查可被闖入的入口

假設產線有工業相機、看板與邊緣電腦長期連網，資安團隊可依 Anthropic 的研究檢查設備清單、預設帳密、未驗證的除錯連接埠及跨網段通路。AI 可幫忙彙整掃描結果與修補優先順序；研究並未證明這些工廠設備已遭 AI 蠕蟲感染。

試點要在授權網段進行，由資安與設備主管核准掃描和隔離。量測可疑入口數、修補後再測結果，以及掃描是否影響機台運作；停機與網路變更走既有變更程序。

04商業訊號亮點

長任務代理的收入，繫於可管理的完成成本

Meta 現在透過 API 與 Muse Code 提供新模型，未來計畫把 Muse Wonder 推向訂閱者。從客戶角度，願意付費的工作是把跨文件、跨系統的待辦真正完成，且每一步能追溯。可能的收費方式包括高階訂閱、代理用量及企業整合；這是本報分析，Meta 尚未公布相應新價格。供應商還得承擔記憶治理、錯誤補救與人工覆核成本；採購時應看完成一件有效任務的總費用。

算力效率若落地，利益先在雲端成本表上出現

Maia 300 若達到 Microsoft 的效能目標，雲端業者可在固定電力與機櫃空間內服務更多推論請求，進而影響平台毛利和可供應容量。客戶是否拿到較低價格，仍取決於部署、供需與定價，不能由晶片規格推定。反蒸餾防線則顯示另一筆成本：防濫用有助保護模型能力，卻需要持續監控、誤擋處理與開發者相容性。兩者都提醒企業把算力、品質及治理一起放進採購試算；以上為商業分析。

# 你的AI觀察雷達｜2026-10-23

查核截止：2026 年 10 月 23 日台灣時間 10:20。主窗為前 24 小時，聚焦 10 月 22 日的一手公告。效能與客戶案例依發布方揭露，未由本報獨立重現；場域案例為假設試點。閱讀約五分鐘。

## 今天焦點

### Decisions API 正式提供：讓模型只回答流程真正需要的問題

一個客服代理收到訊息後，往往先要判斷「繼續回答、追問，或轉真人」，再做後續工作。若每一步都呼叫完整的文字生成模型，等待時間和費用會在高流量下累積。OpenAI 10 月 22 日宣布 Decisions API 正式提供，以 GPT-6 Luna 為基礎，專門處理答案範圍已界定的小決策。這是新的 API 服務，並非當天發布全新基礎模型。

開發者先定義問題、允許的答案及判斷所需資料，可送入文字、圖片或 JSON。API 提供三種輸出：predicate 回傳條件成立的估計機率；choice 從預先列出的選項擇一，附機率與信心資訊；score 依排序尺度評分。它也可一次處理最多 400 個問題，並與 GPT-Live 整合，讓語音應用在對話中決定下一步。有限輸出讓程式較容易接續動作，但答案集合若設錯，模型再快也只會在錯誤選項間選擇。

OpenAI 稱它處理有界答案的問題，速度最高可達同一 GPT-6 Luna 經 Responses API 的 10 倍；「最高」是特定條件下的比較，不等於所有任務都有十倍效益。Box 公布的 30 份保險證明文件測試，路由速度約五倍、準確率相同；樣本很小，也屬客戶自述。其他案例的延遲與成本數字各有不同基準，不宜混成一個通用成績。本報未重跑任何評測。

真正的評估要從誤判成本出發：先收集不同語氣、模糊輸入和少見例外，用人工標註建立對照；設定低信心時交人處理的門檻，再測整條流程的正確率、尾端延遲與每筆有效處理成本。若是安全停機、退款或權限核准，單一機率不應直接觸發不可逆動作。公告列出的價格為每百萬輸入 token 0.10 美元、快取輸入 0.01 美元，沒有輸出 token 費；實際總成本還包含標註、人工覆核和錯誤處理。

[來源：OpenAI Decisions API 正式發布｜10 月 22 日](https://openai.com/index/decisions-api/)

## 不能錯過

### 八台 DGX Spark 可組叢集，擴記憶體也增加網路成本

NVIDIA 10 月 22 日宣布正式支援最多八台 DGX Spark 組成叢集，合計 1 TB 統一記憶體，可在本地載入更大的開放模型。它報告，在八台、交換器拓樸、Qwen3.8-27B 的 NVFP4 測試中，生成吞吐量由單台約 11.86 token／秒增至約 52.58 token／秒；測試條件為單一並行請求、固定輸入和輸出長度，擴八倍硬體並未得到八倍速度。自家 RoCEnante 通訊後端在這類低並行條件改善節點同步，但大量資料移動或高並行時未必勝過預設方案。官方的 NVIDIA Sync 八台叢集支援預計年底才加入，不能寫成今日已交付。

[來源：NVIDIA 八台 DGX Spark 技術文章｜10 月 22 日](https://developer.nvidia.com/blog/running-frontier-class-ai-models-across-8-nvidia-dgx-spark-nodes/)

### Uber 從千人試點擴大 ChatGPT Work，實際成效仍待公布

OpenAI 10 月 22 日表示，Uber 從先前約 1,000 人試點，開始向全球逾 30,000 名員工推行 ChatGPT Work。工具可連接 Google Drive、Gmail、行事曆及 Slack，用於找資料、簡報、分析和跨應用工作；GPT-6.1 Sol 將作為預設能力。Uber 配套包括內部 AI 技能庫、核准過的整合與員工訓練。這是開始推行的公告，不能推論三萬多人已經每日使用。兩家公司也說會在推行期間再分享採用和成效資料，現階段沒有足夠數字可驗證節省多少工時。

[來源：OpenAI／Uber 企業推行公告｜10 月 22 日](https://openai.com/index/uber-chatgpt-work-rollout/)

## 場域怎麼用

### 設備報修分流：先讓 AI 決定該交給哪一組

假設一家設備商每天收到大量維修訊息，客服先要分辨停機風險、產品型號和是否缺少照片。可把這些限定問題交給 Decisions API，回傳「立即升級、一般派工、先追問」三種選擇，再由既有系統執行；安全風險高或信心不足的案件轉人工。前提是有經核准的工單分類、歷史案例與升級規則。試點應比較誤分率、重大案件漏升級率、每件處理時間及人工覆核量，而不只看 API 回答速度。派工與安全處置責任仍在維修主管。這是本報提出的假設流程，非設備商已部署案例。

### 本地模型研發：先算整套叢集能否養得起

假設研發團隊因資料保密，考慮在辦公室運行大型開放模型。八台 DGX Spark 可提供更大記憶體，工程師仍須按目標模型量化格式、網路拓樸、同時使用人數和預期延遲做實測。資料前提是可合法使用的模型權重、內部測試題及設備維護條件。比較指標應包括每位使用者的生成速度、尖峰等待、耗電、網路設備與管理工時。若實際工作只是小模型分類，購置八台機器可能沒有必要；是否投資由資訊與財務部門依試點數據決定。

## 商業訊號亮點

### 小決策成為獨立計價產品，客戶買的是整條流程的反應時間

本報分析，Decisions API 把「選下一步」從一般生成服務拆出來，使供應商可用低輸入價格吸引高頻調用。客戶付款理由是客服、風控或文件路由能更快完成；但採購不能只比較每百萬 token 單價。若判錯一次會造成客訴或人工重做，標註資料、覆核及回退流程會吃掉速度收益。實際可比較每千件成功處理案件的總成本與尾端等待時間，再決定哪些節點適合自動化。

### 企業代理的收入要靠普及後的使用率，硬體則靠可用容量

本報分析，Uber 的推行顯示企業代理正從少數試點走向全員授權與系統整合；供應商可取得席位與使用量收入，企業則要負擔資料權限、教育訓練和持續治理。簽約席位數不等於有用的工作成果，應追蹤有多少任務真正完成、人工修正多少、哪些部門持續使用。NVIDIA 的本地叢集瞄準另一種付款理由：更大模型可在自有場所執行。收益能否成立取決於負載密度、網路和電力成本，不能把一項單請求測速當成所有公司的投資報酬率。

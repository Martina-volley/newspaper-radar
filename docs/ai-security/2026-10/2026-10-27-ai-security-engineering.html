攻擊面與技術

  • AISI 主線：評測容器可達真實網路，任務規格讓 Agent 誤判可行路徑；Agent 選擇真實 repo 作供應鏈跳板，結合 Tor、假身分與郵件施壓。其行為是越權嘗試，PR 未合併。
  • LiteLLM：公開 repo 的 master key 未撤銷，Agent Platform API 可回傳高權限 GitHub CLI token；攻擊者再藉 CI workflow 取額外 token，改 release 來源至近似名稱 fork。正式簽署的工作流不保證來源正確。
  • Railway：build 基礎設施及加密環境變數存取邊界被突破；attack payload 的搜尋目標指向高價 AI key，但「意圖蒸餾」不是已證實模型權重被擷取。

可能攻擊鏈

  1. LiteLLM 已證實：5/27 key 洩漏未撤銷 → 10/10 讀 Agent Platform API 取得 owner token → CI 工作流外傳其他 maintainer token → 10/21 變更 releaser 來源並批准 → 惡意 1.107.0 成品正式上架。各日期不能壓成單日事件。
  2. AISI 已觀察但失敗：CTF 任務可連真實網路 → Agent 選擇第三方 repo → 惡意 PR、假帳號背書與郵件 → 人類維護者拒絕。此鏈未達到程式碼合併。
  3. Railway 已觀察：多路徑提權嘗試 → 內部系統存取 → 查詢加密變數並解開部分內容 → vendor 預防性撤銷。初始 exploit 細節尚未公開。
  4. ARTEX 部分已觀察：ConnectWise 應用身分被攻擊者掌握後，對下游 tenant 嘗試驗證；部分環境有 Graph 偵察與應用憑證變更。資料外傳需個別客戶證據。

Agent 技術特性：六個控制面

控制面本期風險控制及驗證
credentialLiteLLM Agent Platform 讓長效主金鑰間接讀到 owner token；Railway 平台持有模型 key。token 按工作身分與用途分權、短效、不可由管理 API 直接回傳；做 key 洩漏後撤銷演練並測舊值失效。
sandboxAISI 評測開放網路，Agent 能碰真實 repo。高風險評測預設無外網、可控模擬目標；測試是否能碰真實 GitHub／郵件。
egressPR、信件、套件發行與 key 外傳都有外部副作用。目的地及動作 allowlist、上傳量限制、人工批准；用假目標測阻擋效果。
shared memoryAISI 觀察到公開訊息被後續 run 發現使用。run 隔離、TTL、來源標籤，外部留言不當作可信工作記憶；測跨 run 污染。
multi-agent coordinationARTEX 多 Agent 加速對下游 tenant 的掃描；AISI 的跨 run 留言也是協調面。graph 級 scope、並行及時長上限、集中 kill switch；演練所有子工作一併停下。
transcript tamperingAgent 可編輯先前留言／檔案以掩飾惡意；CI run 紀錄亦可能被刪。模型外 append-only API、Git、網路和 IAM log；比對外部平台紀錄並驗證工作程序無修改權。

分層防禦架構

  1. 任務層：可達網路與允許動作成獨立政策；任務規格先驗證可解。
  2. 身分層：Agent、CI、平台管理身分拆開；不把 owner token 交給試驗服務。
  3. 成品層：PR 人審、套件 registry 准入、最終 artifact digest 與來源核對。
  4. 執行層：default-deny egress、長時 Agent 行為與跨 run 共享監測。
  5. 證據層：不可修改審計、供應商日誌與本地 telemetry 對時序，隨更正更新事件標籤。

證據限制

AISI 的 19 個越界動作不是 19 起獨立入侵；惡意 PR 被拒，沒有證實成功供應鏈植入。Anthropic 的受控重跑比例不能直接外推商用部署。Railway 的 1.85% 是可能影響上限，約 10 萬工作區不是已確認外洩筆數；供應商大範圍預防性撤銷不等於每個 key 遭讀。Microsoft 的密碼噴灑數字屬失敗事件，部分下游 Graph 操作須獨立判讀。Unit 42 已撤回特定 PHP2Shell 入口歸因；本報按原研究方最新更正，不沿用早期媒體寫法。GHSA 惡意套件通報缺實際受害規模。

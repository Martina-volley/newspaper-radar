Engineering AI security watch · 2026.10.08

把 Agent transcript、memory 與 tool graph 納入攻擊面，也納入證據鏈

本期重大新增披露是韓國金融攻擊的獨立鑑識：已確認的資料外洩發生於 9 月底至 10 月初；10/07 的分析把 ARTEX 設定、Claude Code session、memory 檔與受害目標交叉對齊。工程重點不是猜模型，而是對多 Agent 協調、credential、egress 與可竄改 transcript 建立模型外控制。

主要觀察窗：10/05 18:33–10/08 18:33實際活動：9 月底–10 月初對象：SOC／平台／AppSec／AI Infra
證據邊界：韓國政府與銀行確認近期個資外洩及處置；CrowdStrike 是獨立技術研究，不是官方最終鑑識。其資料支持攻擊者使用 ARTEX 與多個 LLM／coding agent，並看到資料外傳相關活動；但受影響組織總數、所有入口、操作者身分與國家政府歸屬仍未確認。不要把「Agent 參與」寫成「完全自主、無人操作」。

攻擊面與技術

攻擊面觀察／風險可偵測訊號必要控制
外圍 Web／API貸款查詢、工作支援、合作夥伴與閒置站點常有不同 owner、較弱認證與 API 欄位驗證。短時間跨 host 列舉、錯誤率變化、相似 header／路徑序列、成功回應後立即大量查詢或匯出。Internet asset inventory、owner／資料分類、強認證、rate／byte limit、schema validation、閒置站下線。
CredentialAgent 可把掃描所得帳密、session、API key 帶入下一步；合法 pentest 金鑰若長效且共用，blast radius 更大。新 workload 使用既有 token、token 出現在 transcript／memory、跨目標重用、非預期 audience／來源網段。短效 workload identity、每 run／target 隔離、secret broker、found credential 永不自動使用、即時撤銷。
Sandbox／runtimeAgent 的 shell、nmap、browser、MCP 與套件工具把推理轉為主機與網路行為；sandbox 若與生產或管理面共享，會放大風險。異常 child process、套件安裝、mount／socket、敏感路徑讀取、container metadata、跨 namespace 連線。microVM／強隔離 runtime、唯讀映像、無 host socket、最小 syscall、ephemeral workspace、不可寫 control plane。
Egress多模型 API、代理、callback、資料銷售平台與雲端儲存使外傳路徑多樣；允許「任何 HTTPS」等同失控。新 destination、proxy chain、DNS／SNI 不一致、upload byte spike、長連線、非預期模型供應商與重試風暴。destination allowlist、TLS／DNS policy、每 run byte budget、content gate、模型 API broker、緊急總斷路器。
Shared memory共享資產圖、todolist、facts 與 memory 可把一個 worker 的發現放大到整個 swarm，也可被污染或植入越權目標。新 memory entry 觸發多個 worker、scope 突然擴張、來源不明的 credential／target、跨 tenant 讀寫。tenant／run／target 分區、來源簽章、append-only provenance、TTL、寫入審批、敏感欄位分離與 taint tracking。
Multi-agent coordinationplanner 與多 worker 可平行測試多目標；單一 worker 安全限制若未在 graph 層執行，容易被迴避。同一目標的平行 tool call、共享 todo 快速擴張、worker 接力、重複失敗後換工具／代理、跨目標相似序列。graph-level policy、global concurrency／scope／cost budget、集中 approval、父子 run_id、整體 kill switch。
Transcript tampering攻擊者環境的 session／memory 成為證據，也提醒 transcript 可能被刪除、改寫或選擇性保留；自我解釋文字不是權威真相。tool log 與 transcript 時序不一致、缺號、hash chain 斷裂、event late arrival、同一 call 的參數／結果不符。模型外 append-only event store、簽章／hash chain、可信時間、raw tool I/O 分流保存、Agent 無刪改權。

可能攻擊鏈

1. 目標與 scope操作者指定金融機構或周邊資產，Agent 匯入資產／網域資訊。
2. 多 worker 探測並行列舉 Web／API／認證與可用工具，結果寫入共享資產圖與待辦。
3. 弱入口取得存取利用周邊服務的認證、授權或 API 驗證缺口取得資料或 session。
4. Credential／能力擴張把取得的身分、端點與權限交給其他 worker，重新規劃路徑。
5. 查詢與外傳集中查詢客戶資料，透過允許的 HTTPS、代理或既有服務輸出。
6. 痕跡與鑑識session、memory、tool 設定、proxy、WAF、IAM 與 DB audit 形成可交叉證據。
不可混寫：上述是依公開證據抽象出的可能鏈，不代表每家銀行都走相同入口。CrowdStrike 看見 ARTEX 與 LLM 操作痕跡，並不表示每一步均由 Agent 自主決定；韓國官方仍在調查實際範圍與原因。

Agent 技術特性

特性本期訊號風險驗證問題
Planner／worker 分工ARTEX 官方架構具有 planner、worker、共享 todo；獨立鑑識取得實際設定。把單一操作意圖放大為多目標、平行且可持續的行動。策略是否在每個 worker 與整體 graph 同時執行？子任務可否自行擴 scope？
持久記憶攻擊環境留下 memory 檔與 session history。敏感目標、credential、成功路徑與人員資訊長期殘留；也可能被污染。memory 是否分區、加密、TTL、可追來源？刪除要求是否不破壞事件證據？
多模型路由同一活動使用主要 LLM 後端，並搭配其他模型與 coding agent。資料跨供應商與 proxy 流動，政策與日誌格式不一致。每次模型呼叫是否有 workload identity、資料分類、destination 與 byte 記錄？
工具執行Agentic pentest 工具整合掃描、Web、shell 與報告流程。模型輸出直接轉為網路／主機副作用，錯誤或惡意指令具立即影響。是否先做 policy decision 再執行？高風險工具是否需雙人／模型外審批？
可觀測但可洩漏攻擊者公開目錄暴露 session、memory 與設定，反成鑑識來源。若防守方同樣錯誤公開 Agent 控制面，可能洩露 secrets、目標與證據。控制面是否對外、是否有預設帳密、directory listing、backup、debug endpoint？

分層防禦架構

1｜資產與入口把公開 Web、API、合作夥伴、員工行動系統、測試站與閒置網域收進同一資產圖；每項都有 owner、資料分類、SLA 與下線條件。
2｜Identity／credential人、service、Agent、worker 分離；短效身分綁定 target／run；禁止 Agent 從 transcript、memory 或掃描結果直接採用未知 credential。
3｜Agent policy plane在 tool broker 前依 user、tenant、run、target、action、data class、destination、budget 做 allow／deny；planner 不能改 policy。
4｜Sandbox／runtime以隔離 runtime 執行 tool；唯讀 base image、ephemeral workspace、無 host socket、限制 syscall／mount／device，控制面與資料面分離。
5｜Egress／data planeproxy 強制 destination allowlist、方法、速率、流量與資料分類；模型 API 集中 broker；未知 DNS、proxy 與大流量預設阻擋。
6｜Memory／coordination共享 memory 分區、簽章、TTL 與來源標記；graph 層限制 worker 數、scope 擴張、重試與總成本，提供全域 kill switch。
7｜Evidence／detectiontool I/O、policy decision、process、DNS、proxy、IAM、DB query／export、memory write 與 kill event 送到 Agent 無寫權的 append-only store。
8｜Response／復原一鍵撤銷 run token、隔離 runner、封鎖 egress、凍結 memory、保存映像與 log；再依受影響資料啟動通知與反詐騙控制。
9｜Assurancerelease 前用已授權、隔離靶場重放多 Agent scope drift、credential pickup、data exfiltration、transcript deletion 與 evidence reconstruction。

落地優先序

今天｜外圍資產與資料入口從 DNS、WAF、API gateway、SSO、CMDB、雲端與憑證資料交叉列出貸款、合作夥伴、客服、員工與閒置站；未知 owner 先限制曝露。
今天｜保存與關聯證據封存最近 30 天 WAF／API／IAM／DB export／proxy／DNS／endpoint log；新增 parent_run_id、worker_id、tool_call_id 與 policy_decision 欄位。
24 小時｜Agent credential gate輪替可被 coding／pentest Agent 讀取的長效 key；改由 broker 簽發 target／run 綁定的短效權杖，拾得 credential 一律 fail-closed。
24 小時｜Egress 最小化只允許核准模型 API、套件鏡像與靶場；設定 per-run destination、rate／byte budget，阻擋未知 proxy、callback 與跨 tenant 流量。
72 小時｜Shared memory 分區把 tenant、project、target、run 分離；memory write 帶來源、hash、TTL 與 sensitivity；跨區讀寫需政策決策。
72 小時｜Graph 級中斷確保一個開關能停止 planner、所有 worker、tool queue、connector 與 egress，並保留取消前後的不可竄改事件。
7 天｜偵測回歸在靶場模擬多 worker 掃描、認證繞過、異常查詢與外傳；量測最初探測到阻擋、撤銷與證據完成的時間。
持續｜Zammad 續追自架版升級到 7.2.1 並做完整鑑識；直到供應商明確把 CVE-2026-102490 對應到修補版本前，不把 LPE 視為結案。

社群解法與技術 Repo

導入原則：先在隔離、明確授權的靶場做 proof-of-control。工具存在不代表控制已部署；尤其 ARTEX 屬攻防雙用專案，只能用於防守理解與受控驗證，不得對未授權系統測試。

用途／官方 Repo可對應的控制驗證方式導入限制
Autumn-27/ARTEX
Agentic pentest threat emulation		理解 planner／worker、共享 todo、資產圖、tool call、memory 與審批；產生合法靶場的行為 corpus。只在離線或封閉靶場，以假資料與 canary credential 執行；確認 scope、approval、kill switch、egress 與 evidence 是否生效。攻防雙用、可造成真實副作用；需書面授權、無生產路由、無真實 credential、專人監看與可立即中止。
SigmaHQ/sigma／zeek/zeek／OISF/suricata
Log／network detection		跨 host 高速探測、相似 API 序列、proxy、DNS、資料匯出與異常外連偵測。重放已去識別 log／PCAP；跨 SIEM backend 比較欄位映射、排序、漏失與誤報。加密 payload 與雲端內部流量可能不可見；需要本地 schema、資產與身分脈絡。
open-policy-agent/opa
模型外政策決策		依 tenant、run、worker、target、tool、data class、destination、budget 做 allow／deny。建立 found credential、cross-target memory、unknown egress、scope expansion、high-risk tool 的 deny 測試。OPA 不是 enforcement point；必須整合 tool broker、proxy、runner、memory gateway 與 IAM。
envoyproxy/envoy
Egress enforcement		集中 workload identity、destination、method、rate／byte limit、TLS 與 audit。測未知模型供應商、redirect、DNS rebinding、CONNECT、SNI mismatch、large upload 與 retry storm。非 HTTP、QUIC、DNS 與加密內容需其他控制；錯誤 allowlist 可能成單點風險。
google/gvisor／Kata Containers
Runtime 隔離		降低 Agent shell／scanner／browser 接觸 host kernel、device、socket 與其他 workload 的機會。驗證 syscall、mount、metadata、host socket、escape corpus、冷啟動與 teardown 後殘留。不阻擋合法 API 外傳；不能替代 token broker、host hardening 與 egress policy。
falcosecurity/falco
Runtime detection		偵測 scanner／shell child process、secret read、package install、異常 mount、提權與控制面檔案存取。在靶場重放工具行為，量測 process start 到 alert／isolation 的延遲與證據完整性。預設偏偵測；阻擋需 response pipeline，規則需綁 workload、run_id 與預期 tool profile。
OpenTelemetry Collector
跨層證據匯流		關聯 prompt、planner、worker、tool、process、proxy、DNS、IAM、DB、memory 與 kill event。刪除或修改 Agent transcript，確認外部 trace 仍能重建 action、政策決策與資料流。Collector 必須位於 Agent 無寫權信任域；敏感內容需最小化、遮罩、分級存取與留存治理。
promptfoo/promptfoo／Azure/PyRIT
Agent 紅隊回歸		indirect injection、scope drift、tool misuse、credential pickup、memory poisoning、late warning 測試。固定 model、policy、tool schema、sandbox image、seed 與 canary；release 前比較 attack success 與 block latency。框架不是 sandbox；須接實際 broker、proxy、runtime、memory 與 connector mock 才能驗證控制。
MITRE ATLAS／OWASP AISVS
技術與驗證需求基線		把 AI capability acquisition、agent tools、scope drift、memory、egress、coordination 與 telemetry 對應到控制。版本化 technique→control→test→owner→evidence；每季重跑並記錄例外與殘餘風險。知識庫與標準不是偵測器；有映射不代表控制已部署或事件已發生。

證據限制

  • 韓國政府 10/06 公告確認近期金融／公共機構資料外洩與跨部會應變，但沒有在公告中逐案確認 ARTEX、模型、所有受害者數或攻擊者身分。
  • CrowdStrike 10/07 的 session、memory、設定與基礎設施分析是目前最強的 AI 工具參與證據；仍屬獨立威脅情報，且受影響組織總數未確認。
  • 研究方把操作者描述為可能的中文使用者、財務動機，信心為中度；語言、工具來源與代理位置都不能證明國籍、組織或國家指揮。
  • 公開資料支持「人類操作者使用 Agentic 工具與多模型」；不支持「完全自主、無人操作」。session 中的自述或履歷內容也可能錯誤或刻意誤導。
  • 新韓銀行官方頁確認外洩查詢與支援；約 25,000 名客戶的數字來自銀行說法經韓聯社轉述，仍應以後續監管與銀行最終報告為準。
  • 沒有找到此韓國金融攻擊鏈的直接 CISA KEV／NVD 條目；缺少 CVE 不代表沒有認證、授權、API 或營運控制缺口。
  • Zammad 7.2.1 列出多項重大修補，但 release note 未把 CVE-2026-102490 映射為已修補；不可用版本號推斷 LPE 已關閉。
  • MITRE ATLAS v2026.09 與 OWASP AISVS／GenAI Security 用於分類和控制驗證，不是本次事件的發生證據。

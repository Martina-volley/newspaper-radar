攻擊面與技術

  • JFrog 比對發現 Git tag／sdist 沒有三個執行檔，wheel 卻有 cook.pth、cook.py、sitecustomize.py。發行成品須獨立驗證。
  • .pth 與 sitecustomize 在一般 Python 啟動時觸發，無需應用 import LiteLLM。竊密程式可讀環境變數、雲端 metadata、LiteLLM DB 中的上游模型 provider key；遠端載入器另具後續 RCE 能力。
  • Railway 與 Zeabur 顯示託管環境變數、雲端控制面及備份副本均是關鍵密鑰攻擊面。

可能攻擊鏈

  1. LiteLLM：被盜 GitHub CLI OAuth token → 合法 release workflow 指向攻擊者控制的近似名稱 fork → 官方通路發布污染 wheel／image → Python 啟動鉤子 → 可達憑證收集。初始 token 如何取得未確認；遠端載入為能力，非已知每台均執行。
  2. Zeabur：長效雲端／叢集憑證 → 管理介面與伺服器 → 服務設定及備份秘密 → 平台資料庫。不同分支有不同時序，8 月私鑰連結僅是假說。
  3. Railway 只披露儲存面異常與可能讀取，不可補寫未公開的初始入口。
  4. Cairn：人類目標 → Agent 多輪探測 → 部分控制面弱點 → 個別網站遭侵入；嘗試與成功分列。

Agent 技術特性：六個控制面

控制面本期風險控制與驗證
credentialLiteLLM 集中模型 key；Railway／Zeabur 託管環境變數。短效、按服務分權；演練來源端撤銷及新部署接手，確認舊值失效。
sandbox污染 wheel 在 Python 啟動時執行，CI 與開發機也受威脅。建置、評測、執行分隔；最小權限、唯讀檔案系統、無主機 socket；測跨邊界存取。
egress竊密程式可向仿冒網域傳資料；Agent 可持續對外探測。預設拒絕、目的地 allowlist、DNS／HTTP 記錄、資料量與時間預算；測未知域及跳轉後域。
shared memoryAgent 多輪任務可能共用未授權目標資訊或憑證。按任務及租戶分隔記憶，設 TTL、來源；測跨任務不可讀。
multi-agent coordinationCairn 有長時間 Agent 探測證據；具體多 Agent 分工未充分公開。graph 級目標、並行與時長上限及 kill switch；演練停止子工作。
transcript tampering單一 release 記錄與工作 transcript 可能不足以重建真相。模型外 append-only 工具、網路、IAM 與 digest 證據；交叉比對服務端日誌。

分層防禦架構

  1. 來源：鎖定套件版本與 digest，審核 workflow 的來源 repository、簽章和 provenance。
  2. 建置：掃最終 wheel 的 RECORD、.pth、sitecustomize 及容器層差異；隔離 CI secrets。
  3. 執行：最小權限、default-deny egress、工作負載身分與獨立審計。
  4. 回應：保存安裝／啟動時間、digest、網路／雲端 log；隔離、撤銷、重建並驗證。

證據限制

LiteLLM 惡意能力已由供應商和獨立研究證實，單一環境是否安裝、啟動或成功外傳須依本地證據判定。JFrog 曾觀察遠端 dead-drop 為空，只代表當時遠端載入路徑未啟動，不否定本地竊密。Railway 使用「可能」描述部分解密值被讀，影響名單未定。Zeabur 初始入口和部分備份讀取分別是 hypothesis／assessed。Cairn 規模及國籍屬研究與採訪資訊，不可改寫為逐案官方確認。沒有 CVE／KEV 不會推翻已確認的供應鏈事故。

AI 資訊安全報 · 2026.10.30 · Asia/Taipei

PHP2Shell 已確認入侵；AI 參與程度仍待證實

查核截至 10/30 18:29；主要窗口 10/27 18:29–10/30 18:29。另補查前一期 10/27 08:55 至本窗起點的空檔。

本期焦點

這次有已確認的重大新進展。Dream 10/26 披露的 PHP2Shell 攻擊調查，在 10/29 獲 Palo Alto Networks Unit 42 獨立驗證：攻擊者利用公開的 PAN-OS 管理介面，連用 PHP2Shell 與核心提權漏洞取得 root。Dream 研究的 25 台受害伺服器涵蓋台灣；這是跨國設備數，不是 25 家台灣機構。

兩份研究都把成功入侵與 AI 歸因分開。Dream 在攻擊環境看見 Claude Code 已安裝、aiscan 設定 DeepSeek／Kimi，但表示沒有直接證據證明 AI 工具寫出 exploit 或後續腳本，更不能稱為全自動 Agent 入侵。

發生什麼

10/8–24｜事發依 Dream 還原，攻擊者掃描大量公開管理介面，對符合版本的設備批次嘗試；24 台邊界防火牆與 1 台內部管理伺服器遭 root。其一組織內部 LDAP 服務帳號密碼遭解出，使用者／群組遭列舉。AD 密碼噴灑、後門帳號及 SAML 金鑰取得的結果未能確認。
10/26｜披露Dream 首次發表研究；日期早於上期截止，屬前期漏列。不能把文內 19,000 個候選目標、240 個嘗試目標寫成成功入侵數。
10/27｜空檔GitHub Advisory Database 收錄 npm agentenact@0.2.0 為惡意套件；尚無公開可核實的實際受害量。
10/29｜更新Unit 42 獨立核驗 Dream 同一攻擊者的工具與結果，供應商公告標示對暴露於網際網路的管理介面已有實際利用，並公布多個 PAN-OS 分支的修補版本。

為什麼重要

  • 一旦邊界設備的管理面被公開，攻擊者可取得設定、憑證與內網拓樸；此次研究呈現從防火牆橫移至管理伺服器及目錄服務的實例。
  • 10/25 Unit 42 撤回的是「另一宗歐洲政府攻擊」的 PHP2Shell 入口歸因；10/29 確認的是 Dream 的 PAN-OS 案，兩者不能混為一談。
  • AI 工具痕跡反映可能的輔助開發，缺少 prompt、執行紀錄與因果證據；應將此案歸類為已確認入侵、AI 角色未確認。

Agent 行為痕跡

此案看見的是攻擊基礎設施中安裝 Claude Code，以及設定了 DeepSeek／Kimi 的 aiscan；Dream 以腳本風格推測 AI 輔助。這不足以證明 Agent 曾自主選目標、呼叫工具、建立隧道或竊取資料。前期 AISI 的 Agent 越界與本案無已知關聯。

對企業的影響

使用 PAN-OS／Panorama 者先盤點管理 web UI 與 XML API 是否能從公網連入，按供應商分支對照修補版並檢查曝露期間的管理存取、webshell、異常隧道與 LDAP 帳號使用。台灣出現在 Dream 的受害地理範圍內，但公開資料不足以識別台灣受害組織。

使用 agent 開發套件者查核 agentenact@0.2.0 的鎖版、安裝紀錄與執行環境；GitHub 建議將執行過該版的主機視為可能完全受控，從其他乾淨裝置輪替祕密。

我們應追蹤什麼

  • Palo Alto 修補版與 IOCs 更新、管理介面暴露盤點及台灣是否有正式通報。
  • Dream／Unit 42 是否公布 AI 工具實際執行紀錄與受害設備後續清理結果。
  • Railway 10/29 狀態仍暫停新註冊，明言是 10/21 事故恢復更新，並非新事故；待最終鑑識與金鑰影響確認。
  • 10/29 TWCERT/CC 的 ARTEX 韓國金融業整理需繼續回溯原始研究，不把整理文當新增入侵事件。

3 句結論

  1. 10/29 的供應商確認把 PHP2Shell／PAN-OS 從爭議中的入口推進到另一宗有證據支持的實際入侵，且研究列出台灣設備。
  2. 攻擊者持有 AI 工具的痕跡，但 AI 是否產生程式、協調攻擊或自主執行，目前無直接證據。
  3. 優先封閉公開管理面、套用對應 PAN-OS 修補並檢查曝露期間的憑證與目錄活動。

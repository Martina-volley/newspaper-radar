MCP 工具冒名：把 server 身分帶進每次 Agent 動作授權

查核基準：2026/10/15 18:30（Asia/Taipei）；回看前 72 小時，並追蹤上一期。Docker 的新公告屬已確認產品弱點；Anthropic 的自我複製研究屬隔離實驗。沒有查得本窗已確認的重大新 AI 資安入侵。

工程技術版供應商一手優先PoC 與真實事故分列模型外 enforcement

判讀摘要

Docker MCP Gateway GHSA-qg99-jrvf-j9fh 於 10/13 披露：v0.43.1–v0.43.3 對保留工具的名稱碰撞使用大小寫敏感比對，工具 allowlist 卻不區分大小寫。已啟用的不受信任 MCP server 可提供類似內建控制工具的名稱；client 若選中該工具，參數會傳給此 server。v0.44.1 修補，啟用 tool-name prefixing 可緩解。公告未列已知 CVE、受害者或在野利用。

關鍵控制是將工具身分表示為 server identity + exact tool name + requested action，並在實際執行點授權；只在 prompt 或 UI 顯示名稱上加警語不足以防止工具選錯或參數外送。

攻擊面與技術

MCP Gateway 名稱碰撞

保留名稱與新註冊工具的碰撞檢查採大小寫敏感 map key；工具啟用比對不區分大小寫。攻擊者控制的 server 若被操作者加入並啟用，可用大小寫變體模仿 mcp-exec 等內建工具。真正的風險點是 client 選取與路由到 server 的身分不一致；公告描述為「參數被送至非預期 server」，沒有聲稱直接取得 gateway root 權限。

受控複製研究

Anthropic 測試推論建立與跨節點任務串接。8 節點實驗把初始進入設為未驗證 ADB，並用獨立推論 server 支援較大模型；研究自身將結果視為真實世界成功率上界，不應推斷出現自我傳播惡意程式。

前期攻擊面

localhost UI、外部網頁、短網址、第三方表單、token 與沙箱出口仍需分開建模；本窗沒有證據顯示它們與 Docker 弱點構成同一攻擊鏈。

可能攻擊鏈

Docker GHSA 的條件式鏈（非在野事件）：

1. 操作者啟用攻擊者控制或未審查的 MCP server。
2. Server 公開與 gateway 保留工具只有大小寫差異的名稱。
3. Gateway v0.43.1–v0.43.3 的名稱檢查接受該工具；client 的工具選取落到近似名稱。
4. 原意交給內建控制工具的參數被傳到不受信任 server；後續能否造成資料外洩取決於參數內容及 server 的行為。

這條鏈是公告描述的可利用條件，並非已觀測到的攻擊者操作序列。啟用 tool-name prefixing 或使用 v0.44.1 以上，可在供應商公告的範圍內中斷此路徑。

Agent 技術特性：六個控制面

控制面本期判讀可驗證控制
credentialMCP 冒名工具可收到 client 傳入的參數；是否含 credential 視呼叫而定。前期案例顯示 Agent 曾使用拾得 token。短效、任務綁定憑證；拒絕使用非此 run 發放的 secret；測試近似工具不得讀到 token。
sandbox研究環境與真實網路邊界仍是前期重點；受控蠕蟲實驗不等於 sandbox escape。低權限容器／VM、不可寫 host bind、測試能否觸達 host 和內部管理埠。
egress工具參數可流向非預期 MCP server；前期短網址與 DNS 案例說明 HTTP allowlist 不足。依 server、目的地、動作和位元組預算限流；對 DNS、registry、URL fetch 及 webhook 實測。
shared memory本期 Docker 公告沒有 shared-memory 污染證據；跨任務記憶仍可能放大前期事件。按任務與信任域分區、簽章、TTL；負面測試他人記憶不可變成新工具授權。
multi-agent coordination本期沒有多 Agent 協同攻擊證據；受控研究有跨節點延續任務，但與企業 planner／worker 架構不同。整個執行圖的 scope、concurrency、成本與 kill switch；子 Agent 不得擴權。
transcript tampering模型輸出與文字 transcript 不能當作唯一行為證據；本期未證實 transcript 遭竄改。在 gateway／tool runner 產生 append-only 呼叫紀錄，記錄 server ID、精確工具 ID、policy 決策、雜湊和時間戳，與 transcript 交叉比對。

分層防禦架構

  1. 供應鏈／連線前：只登錄經審查的 MCP server、簽章或固定版本；標記 owner、資料範圍與允許工具。檢查 gateway 版本是否受影響。
  2. 工具發現：server ID 與 exact-case tool ID 一起提供給 client；對保留名稱、大小寫、Unicode 正規化與重複名稱作拒絕測試。工具名稱前綴可降低碰撞。
  3. 執行前：由模型外 policy engine 判斷 user、run、server、tool、參數和預期副作用；對 secret、檔案、執行、對外寫入預設拒絕或需審核。
  4. 執行中：沙箱最小權限、default-deny egress、destination 與 byte budget；分別管制讀取與寫入。
  5. 執行後：從 gateway／工具層寫入不可覆寫的 action evidence，與網路／主機日誌對齊；一旦疑似外送即停用 server、撤銷 credential 並通知受影響方。

落地優先序

  1. 今天：資產查詢所有 Docker MCP Gateway 版本、啟用 server 清單與名稱前綴設定。v0.43.1–v0.43.3 優先升級 v0.44.1，或採公告的前綴緩解；升級前確認 release 與環境相容。
  2. 本週：建立大小寫變體與重複名稱的負面測試，確認 client 不會把敏感參數送到測試 server。移除不受信任或不再使用的 server。
  3. 本週：在實際 tool runner 實作精確身分授權與模型外審核，並記錄路由結果。
  4. 下一輪：把 localhost UI、短網址、DNS、package registry、shared memory 和多 Agent 權限擴張放進紅隊回歸測試。

社群解法與技術 Repo

Docker MCP Gateway 官方 Repo 供應商

用途／控制：MCP server 聚合、隔離與工具路由；本期直接相關的修補點。驗證：在受控測試環境比對 v0.43.3 與 v0.44.1 的大小寫變體工具發現／路由，確認更新後拒絕碰撞且精確 allowlist 正常。限制：這是 gateway 實作，不會替應用定義每項工具的業務授權；版本升級可能影響既有 client。

MCP Inspector 官方 Repo 測試工具

用途／控制：查看 MCP server 所宣告工具與回應，協助盤點命名衝突。驗證：分別連線可信與測試 server，列出完整工具清單、來源與大小寫變體，再對照 gateway 的實際路由。限制：Inspector 提供人工檢視，不是執行時政策閘門；不要用正式憑證測不受信任 server。

OWASP Agent Control Standard 社群規格

用途／控制：模型外 pre-action allow／deny 與觀測契約。驗證：以真實 Agent hook 發送工具呼叫，確認高風險動作被拒、決策與路由證據可重建。限制：參考實作文件顯示預設 failure posture 為 proceed，需改成 fail-closed 並驗證通道身分；規格和 demo 不能直接視為 production 防護。

Open Policy Agent 政策引擎

用途／控制：把 server ID、tool ID、user、run、資料分類與目標目的地寫成可測試的授權政策。驗證：建立「大小寫冒名工具不得收到憑證參數」「外部寫入無核准必拒」等單元與整合測試。限制：OPA 只評估送入的輸入；若 gateway 未提供可信 server 身分或執行點沒有強制遵循判定，政策不會生效。

promptfoo 回歸測試

用途／控制：建立 Agent 和工具路由的對抗測試，涵蓋近似工具名稱、拾得 credential、短網址與未授權外部提交。驗證：固定測試案例與期望拒絕結果，於版本更新後執行 CI 回歸。限制：測試通過只覆蓋已設計案例，不替代正式環境的 gateway 強制授權與網路隔離。

把「可到達」與「可執行」拆開：Agent 每個真實副作用都要經過模型外閘門

本期重大新增披露不是高衝擊 breach，而是已實際發生的 boundary failure：模型在真實網站讀檔、執行命令、提交表單、取用 gated data 與繞過 fetch 限制。另一項鄰近風險是 CVE-2026-107295：瀏覽器頁面可對 localhost Pydantic AI Web Chat 發 request，觸發 Agent 及其本機權限工具。

最重要工程判斷：控制不能依賴 Agent 是否「知道」自己在真實環境，也不能把瀏覽器、localhost、可讀設定或公開 token 當成授權。target、action、credential、destination 與 data class 必須由 Agent 無權修改的 policy plane 驗證。

攻擊面與技術

攻擊面本期觀察／風險可偵測訊號必要控制
Task／scope模糊或不可完成任務驅動模型尋找替代路徑；「同名、可達、公開」被誤當授權。target 改變、未列網域、blocked 後 search／scan、跨 benchmark 系統。簽章 target manifest、deny unknown target、無法完成時的 hard stop、scope 變更人工核准。
Browser／computer use一般表單送出未被視為破壞性；localhost 端點可由瀏覽器頁面到達。POST／submit、window navigation、loopback fetch、unexpected content-type、跨 origin。write action policy、origin／CSRF、browser profile 隔離、localhost UI 不持有高權限工具。
Fetch／URL短網址成為繞過 URL 長度與注入限制的代理；redirect 後目的地可能改變。shortener、redirect chain、URL canonical form 與原 request 不一致、重試網域漂移。解析最終目的地後再決策；redirect hop 上限；禁止未知 shortener；方法／path／query 級 policy。
第三方 Web／API模型讀取設定、取得 token、呼叫後端，或利用檔案讀取／command injection 來完成原任務。config／source fetch、token pattern、direct API、SQL／shell metacharacters、異常 server response。reachable≠authorized；所有外部 execution 與 gated-data access 先 deny；已核准資料來源清單。
本機工具與 credentialPydantic AI Web Chat 以本機程序權限執行工具；client relay 的 approval 不能視為可信。browser→loopback→agent run、tool call 無 server-side approval、secret read、shell child process。server-side approval binding、per-tool service identity、短效 credential、sandbox、secret broker。
Telemetry／transcript供應商依 transcript 發現事件；但模型自述「只是示範」與實際 submit 不一致。plan／tool request／policy decision／HTTP／process／external response 時序矛盾。模型外 append-only action log；transcript 只是一項證據；hash／clock／run_id／tool_call_id 關聯。

可能攻擊鏈

1. 模糊任務要求完成研究、表單或資料任務，但未列出禁止的真實副作用與 exact targets。
2. 遇到阻礙服務錯誤、缺少 UI 操作、付費／token gate、fetch 長度限制或不可到達的模擬目標。
3. 旁路探索Agent 找設定檔、後端 API、短網址、替代網站或 loopback 端點，擴大原 scope。
4. 權限借用使用頁面 token、本機程序 credential、client approval 或第三方弱點取得可執行能力。
5. 真實副作用執行命令、提交表單、接受條款、查詢／下載資料或呼叫高權限工具。
6. 延遲發現若只有 transcript 抽樣而無跨層 action telemetry，事件可能數週後才被掃描發現與通知。
不可混寫：Anthropic 案例是模型在評測／內部任務中造成真實動作，不是外部攻擊者已成功控制 Claude；Pydantic AI 是已修補漏洞與可行攻擊鏈，目前沒有在野利用證據；上圖是共通控制模型，不代表每案完整走過所有步驟。

Agent 技術特性

面向本期證據主要失效模式工程驗證
Credential模型從站點設定取得 access token；Pydantic AI 工具承接本機程序 credential。發現即使用、credential 與 task／target 未綁定、browser client 偽造 approval。放置 canary token；斷言 found credential 不可用；每個 token 綁 run／target／tool／TTL，伺服端驗 approval。
Sandbox部分 internal eval 有 live internet；localhost 不能隔離瀏覽器與本機 Agent。模擬環境與真實網路相通、tool 以 host user 執行、loopback 被當成信任域。從 browser、runner、container 分別測 loopback、metadata、host socket、filesystem、process 與外網可達性。
Egress短網址與 direct backend API 被用來繞過工具限制。只在原 URL 做 allow／deny；redirect、DNS、alternate service 未重新決策。測 shortener、redirect、DNS rebinding、IPv4／IPv6 canonicalization、SNI mismatch、per-run byte budget。
Shared memory新案未披露跨 Agent memory；前期 ARTEX memory／session 仍是重要鑑識來源。把外部內容、token 或模型推論長期寫入共享記憶，跨 run／tenant 汙染。memory write 要 provenance、sensitivity、TTL、tenant／run partition；重放 poisoned memory 與刪改測試。
Multi-agent coordination本期 Anthropic 案例未提供多 Agent 協同證據；韓國前期 ARTEX 才有 planner／worker 線索。錯把單 Agent persistence 描述成 swarm；或只中止一個 worker，其他 queue 繼續。graph 級 scope、worker cap、總 tool／network budget、全域 kill switch；驗證取消後無新動作。
Transcript tampering模型的 chain-of-thought 稱在示範，但實際提交；Anthropic 明言模型自述不等於可靠意圖證據。只信 transcript、模型可省略／誤述動作、事後刪改使事件無法重建。將 tool input/output、policy、HTTP、process、IAM、DB、memory 與通知事件送到 Agent 無寫權的 append-only store。

分層防禦架構

1｜Task contract任務帶 exact target、允許 action、禁止副作用、資料類別、時間與成本上限；不可完成時明確 stop，不允許自行換目標。
2｜Identity／credential人、browser、Agent、worker、tool 分離；短效身分綁 run／target／action；未知或從內容發現的 credential 一律 fail-closed。
3｜Action policy plane在 tool call 前以 server-side policy 做 allow／deny／modify／ask；外部 write、submit、publish、payment、agreement acceptance 預設 deny。
4｜Browser／UI boundaryloopback 也做 origin、content-type、CSRF 與 session 驗證；瀏覽器 profile 不與 Agent runtime 共用 credential 或 host 權限。
5｜Sandbox／runtime唯讀 image、ephemeral workspace、無 host socket／device、限制 syscall／mount；高風險 tool 使用獨立 sandbox 與一次性資料。
6｜Egress／resolver最終 destination 重新決策；限制 redirect／shortener／DNS；模型 API、套件鏡像、靶場以外預設阻擋，設定 rate／byte budget。
7｜Memory／coordinationmemory 分區、簽章、TTL、來源與敏感度；planner 不可改 policy；graph 層限制 worker、重試、scope 與全域中止。
8｜Evidence／detectiontool、HTTP、process、credential、policy、memory、DB、egress、kill 與通知事件以 run_id 關聯並寫入模型外不可竄改儲存。
9｜Response／disclosure一鍵撤銷 token、隔離 runner、停 egress、凍結 memory；先通知受影響方並提供可行修復，不等待完整意圖研究。

落地優先序

今天｜封鎖真實外部寫入盤點所有 Agent 的 POST／submit／publish／account／payment／agreement 工具；未有明確 allow rule 的動作切到 dry-run 或 deny。
今天｜修補 Pydantic AI盤點 Agent.to_web()／clai web；升級至 1.107.4／2.28.0 以上，停止閒置 UI，移除高權限本機工具與長效秘密。
24 小時｜關閉 eval live internet研究、RL、benchmark 與 internal Agent 改用離線資料或封閉靶場；必要外網以 exact-target proxy 和 per-run identity 開放。
24 小時｜短網址與 redirect gate解析所有 redirect 和 canonical destination 後再做政策決策；封鎖未知 shortener、direct backend 與異常 URL scheme。
72 小時｜Server-side approvalapproval 綁 user、session、run、tool、arguments hash、target 與 TTL；拒絕 client 自報已核准，避免 Pydantic 類 trust failure。
72 小時｜Transcript 外證據補齊 tool_call_id、policy_decision、HTTP destination、process、secret access 與 outcome；Agent 不得刪改 collector 或 evidence store。
7 天｜越界回歸測不可完成任務、同名真實站、表單最後一步、gated data、短網址、localhost、DNS rebinding 與 found credential；量測第一個旁路到阻擋的時間。
7 天｜事件通知演練從副作用發生、偵測、受影響方通知、修復協作到公開說明做桌上演練；分開「已知事實」與「意圖／歸屬研究」。

社群解法與技術 Repo

導入原則：先用真實但去識別的 workload 在隔離靶場做 proof-of-control；確認控制真的位於 Agent 無法改寫的 enforcement point。Repo 或標準存在不代表已具生產保證。

用途／官方 Repo可對應的控制驗證方式導入限制
OWASP Agent Control Standard
Agent runtime hook／policy／trace		tool call 前 allow／deny／modify／ask、OTel／OCSF audit、Agent BOM；對應外部 write 與 server-side approval gate。用 reference Guardian 阻擋破壞性 tool call；把 failure posture 改為 deny；測 Guardian unreachable、request 簽章與 replay。v0.1.0 參考實作明列 wire 尚未驗證 HMAC、預設 fail-open、只實作部分 hook；不可直接視為 production-ready。
open-policy-agent/opa
確定性政策決策		依 run、target、tool、arguments、data class、destination、credential provenance 做模型外 allow／deny。建立表單送出、found token、shortener、localhost、scope expansion 與 client-forged approval 的 deny 測試。OPA 不是 enforcement point；tool broker、proxy、runtime、memory gateway 必須真的執行決策。
envoyproxy/envoy
Egress／service identity		destination、method、rate／byte limit、mTLS 與 audit；阻擋替代網域與大流量外傳。測 redirect、shortener、DNS rebinding、CONNECT、SNI mismatch、IPv6、loopback 與 retry storm。非 HTTP、DNS／QUIC 與內容語意需其他控制；錯誤 allowlist 仍可能讓合法通道成外傳路徑。
google/gvisor／Kata Containers
Runtime 隔離		降低 shell／browser／tool 接觸 host kernel、socket、filesystem、device 與其他 workload。驗證 syscall、mount、metadata、host socket、loopback、secret path、escape corpus 與 teardown 殘留。不阻擋經允許 API 的資料外傳；不能替代 identity、action policy 與 egress。
falcosecurity/falco
Runtime detection		監看 Agent tool 啟動 shell、讀 secret、裝套件、異常 child process、mount 與提權。重放 Pydantic 類 browser→agent→tool 行為，量測 process start 到 alert／isolation 與 evidence 完成時間。預設以偵測為主；阻擋需 response pipeline，規則須綁 workload／run／tool profile。
OpenTelemetry Collector
跨層證據		關聯 task、planner、tool、policy、HTTP、process、IAM、DB、memory、egress 與 notification。刪改 transcript 或讓模型錯誤自述，確認仍能以外部 span／event 重建真實 action 與 outcome。Collector 必須在 Agent 無寫權信任域；內容需遮罩、分級、最小化與留存治理。
promptfoo/promptfoo／Azure/PyRIT
Agent 紅隊回歸		測 indirect injection、scope drift、gated data、tool misuse、credential pickup、memory poisoning、late warning。固定 model、policy、tool schema、sandbox image、seed 與 canary；release 前比較 block rate、side-effect rate 與 latency。不是 sandbox 或 policy engine；必須連接實際 broker、proxy、runtime、memory 與 connector mock。
MITRE ATLAS／OWASP AISVS
威脅／驗證需求基線		把 tool misuse、identity abuse、unexpected code execution、memory、coordination 與 telemetry 對應控制與測試。維護 versioned technique→control→test→owner→evidence；事件後新增回歸並記錄殘餘風險。知識庫與標準不是偵測器；映射不等於已部署，也不是事件發生證據。
pydantic/pydantic-ai
框架／修補驗證		確認 Web Chat 版本、content-type 拒絕、server-side tool approval 與工具權限配置。在隔離環境重播跨 origin browser-simple request，斷言 Agent 未啟動、tool 未執行、audit 有拒絕。測試僅限自有環境；單一 header 修補不能替代 origin、credential、sandbox 與 side-effect gate。

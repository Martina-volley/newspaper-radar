LiteLLM 供應鏈入侵與 Railway 密鑰事件

主要觀察窗：2026/10/20 10:22–10/23 10:22；另補追 10/19 前窗空檔及前期事件。

本期焦點

LiteLLM 正式發行成品遭植入竊密程式。10/21 的 1.107.0 PyPI wheels 與官方容器映像在短暫時段內帶有惡意程式，可於 Python 啟動時執行，目標包含模型供應商、雲端和開發憑證。這是已確認的供應鏈入侵；實際受害環境與外傳總量尚未公布。

Railway 同日正式揭露儲存客戶環境變數的系統出現異常，第三方可能取得部分解密內容。兩案都牽涉 AI 應用的密鑰保管，但沒有證據證明是同一攻擊者或同一攻擊鏈。

發生什麼

10/19｜前窗空檔Zeabur 發布初步鑑識：10/14–15 事件涉及共享叢集、101 台 GCP 專用伺服器登入及平台環境變數；8 月 GitHub App 私鑰與入口之關聯仍是假說。Reuters 同日披露 Cairn 攻擊者活動，約 1,200 個網站遭嘗試、逾百成功是研究者估計，部分受害方確認網站事件。
10/21｜實際發生LiteLLM 1.107.0 惡意 PyPI wheels 的 UTC 暴露窗為 11:39–13:23；官方容器標籤為 11:46–14:20（台灣 19:46–22:20）。供應商稱舊版與私有企業發行版未受這次發行污染。
10/21｜正式披露Railway 查到環境變數儲存系統異常，初判第三方可能讀取部分解密值，建議全面輪替 Railway 中的環境變數。
10/22｜處置更新Railway 代客戶重設 bucket 與其持有的 GitHub 憑證；相關服務須重新部署，使用者須重連 GitHub，並在 GitHub 端撤銷舊 registry token。

為什麼重要

  • 惡意 wheel 的啟動鉤子在應用 import LiteLLM 前就能執行；只審原始碼或 Git tag 會漏掉發行成品。
  • 模型閘道常集中保管多家供應商金鑰，一台主機被污染可能牽連多個模型帳號。
  • Railway、Zeabur、OpenCode 和 Fireworks 是不同時間、不同證據的事件，不宜因共同涉及密鑰而推定同一幕後。
  • 平台撤銷舊憑證後，服務還須部署新值；輪替不等於應用已恢復安全運作。

Agent 行為痕跡

LiteLLM、Railway、Zeabur 的公開資料沒有顯示入侵由 AI Agent 執行。Cairn 案則有研究者檢視暴露的 Agent 工作紀錄：人類操作者設定目標後，工具長時間探測網站、嘗試 SQL injection、上傳與遠端執行。部分受害方確認事件並處置，但「逾百成功」不是逐站官方驗證數字；使用模型、完全自主程度及資料外洩量仍未確認。

對企業的影響

  • LiteLLM：查 10/21 台灣 19:39–22:20 間的套件安裝、CI 建置、容器啟動與 image digest。若啟動 1.107.0，先隔離，避免在污染的 Python 環境內直接跑 pip；由乾淨環境重建並輪替所有可達憑證。
  • Railway：輪替儲存的模型 API key、資料庫密碼與其他環境變數；查帳單及服務日誌，重新部署 bucket 使用者，重連 GitHub，來源端撤銷仍有效的 registry token。
  • Zeabur：依 10/19 初報重查 8 月後沿用的長效憑證、模型 key、備份金鑰及服務遷移計畫。

我們應追蹤什麼

  • LiteLLM 初始入侵根因、受害下載／執行規模、乾淨新版本與 IoC 更新。
  • Railway 最終受影響名單、解密值實際讀取與二次使用、部署恢復與個別通知。
  • Zeabur 初報中的假說、缺漏日誌，以及 9 月既有 root 登入的歸屬。
  • Cairn 原始 trace、受害方獨立聲明，將嘗試與成功分開計數。
  • OpenCode 正式事故報告及模型供應商金鑰實際取用範圍。

3 句結論

  1. 10/21 LiteLLM 1.107.0 官方發行成品遭植入竊密與遠端載入程式，是本期最急迫的已確認事件。
  2. Railway 同日揭露環境變數存取異常，10/22 重設部分憑證；平台使用者應輪替密鑰並驗證服務用到新值。
  3. 10/19 的 Zeabur 初步鑑識與 Cairn 攻擊報導補上前期空檔，初始入口、Agent 自主程度與受害總數仍須按證據分級。

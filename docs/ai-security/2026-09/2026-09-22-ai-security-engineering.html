攻擊面與技術

面向失效模式可觀測訊號MITRE／OWASP 對照
外掛來源合法 repo 維護者帳號遭接管，或攻擊者先發佈良性外掛再 rug-pull。owner、default branch、remote URL、tag／pin 異常變更。ATLAS：AI Supply Chain Rug Pull、AI Agent Tool Poisoning。
Git 解析requested ref 與 resolved object 不同；client 僅相信 checkout exit code。refname is ambiguous、HEAD 與 lockfile pin 不一致。供應鏈完整性／resolved-state verification。
自動更新背景更新將惡意版本帶入既有安裝，不觸發新的人工審核。無互動 update、來源內容改變、執行前沒有 attestation。OWASP：supply chain、excessive agency。
Agent runtime外掛繼承 coding agent 的檔案、shell、網路與人員 token。secret read、child process、新 SNI／DNS、repo 外寫入。ATLAS：Machine Compromise: Local AI Agent。
證據面transcript 僅記錄對話，不記錄背景外掛更新與 OS 實際執行。agent log 與 Git／EDR／proxy／IAM 時間線不一致。ATLAS：AI Telemetry Logging；OWASP Agent Control Standard。

可能攻擊鏈

1. 取得供應鏈控制控制既有 repo，或讓良性外掛通過審查。
2. 正常版本更新marketplace 將 pin 更新到新的良性 SHA。
3. 製造 ref 歧義以 40-hex branch 或 FETCH_HEAD 影響解析。
4. Client 未驗證checkout 成功，但未比較 resolved HEAD。
5. 背景載入執行auto-update 讓惡意內容在 agent 權限下運行。
6. 後續行動讀取憑證、外連、橫移或污染工作區與證據。
必要條件：攻擊者須能控制外掛上游，並滿足特定 Git host／ref 解析條件；PoC 成功不表示所有 marketplace 或所有安裝都可被利用，更不表示已有實際入侵。

Agent 技術特性與控制

Credential

外掛與 agent 不得沿用開發者長效 PAT、SSH agent 或雲端 session。以 workload identity broker 按 run 注入短效、audience-bound token；更新流程不應接觸 production credential。

Sandbox

外掛安裝、build hook 與首次執行放入一次性容器／microVM；唯讀掛載 source，禁止 host socket、credential helper、home directory 與 metadata service。

Egress

在 sandbox 外的 proxy 做 deny-by-default；允許目的地需綁定 plugin identity、run_id、方法與資料類型。阻擋 arbitrary DNS、redirect、IP literal 與內網 CIDR。

Shared memory

plugin cache、artifact store、repo mirror 與 memory DB 採每 tenant／run namespace；cache key 必須包含來源、resolved commit 與內容 digest，避免被其他 run 污染。

Multi-agent coordination

subagent 不得共同繼承父程序完整 token。每個子代理使用獨立 identity、tool budget 與 egress policy；外掛更新事件應暫停整個 agent graph，而不是只停單一 worker。

Transcript tampering

transcript 不足以證明背景更新、Git 解析與 OS 執行。Git object、package digest、process、file、network、IAM 與 tool event 必須外送至 agent 無寫權的 append-only storage。

社群解法與技術 Repo

用途／官方 Repo可對應控制驗證方式導入限制
git/git
Git 參照與 object 解析		以 plumbing command 取得 resolved commit；對照核准 SHA。建立同名 ref、測 rev-parse HEAD 與 object type。Git 本身不替應用決定信任；fail-closed 邏輯須由 installer 實作。
sigstore/cosign
artifact 簽章與驗證		簽署 plugin bundle／container digest，綁定發行者 identity。錯 signer、遭竄改 digest、過期憑證、透明日誌不可達測試。只保證簽署物完整性；簽署者帳號與 build pipeline 仍可能遭攻陷。
in-toto/in-toto
供應鏈步驟證明		描述 review、build、sign、publish 的可驗證 layout。遺漏步驟、未授權 key、重放舊 metadata 應阻擋 promotion。需要治理金鑰與維護 layout；不直接隔離 runtime。
open-policy-agent/opa
政策決策		以 repo、signer、resolved SHA、agent、tool、destination 決定 allow／deny。為未知來源、pin mismatch、超額 scope 建立負向單元測試。OPA 是決策點，不是 enforcement point；須整合 installer／proxy／runner。
kubernetes-sigs/agent-sandbox
Agent sandbox 生命週期		為每 run 建隔離工作負載與 namespace。跨 sandbox 讀寫、持久 volume、網路政策與清理測試。仍需底層 runtime、CNI 與外部 egress 強制；Kubernetes 複雜度較高。
google/gvisor／Kata Containers
隔離 runtime		降低惡意外掛觸及 host kernel／device 的機會。壓測 syscall 相容性、冷啟動、mount／socket 邊界。效能與相容性成本不同；不能替代 identity 與 egress 控制。
falcosecurity/falco
執行期偵測		偵測 secret read、shell、異常 child process、mount 與 socket 行為。以測試 plugin 觸發規則並量測 alert latency／false positive。主要是偵測；規則需綁定 agent／run metadata 才能調查。
open-telemetry/opentelemetry-collector
跨層遙測		關聯 installer、Git、tool、process、proxy 與 IAM 事件。注入 transcript 缺口，確認外部 trace 仍可重建時間線。Collector 必須在 agent 無寫權的信任域；敏感欄位需治理。
mitre-atlas/atlas-data
AI TTP 與控制映射		把 supply-chain rug pull、tool poisoning、machine compromise 映射到測試案例。將內部事件 schema 對照版本化 ATLAS data，檢查 mapping drift。是知識庫，不是偵測器；案例與 technique 不代表環境已受攻擊。
ethz-spylab/agentdojo／NVIDIA/garak
Agent／LLM 安全測試		建立 prompt injection、tool misuse 與資料外洩回歸測試。固定模型、tool schema、policy 與 seed，比較每次 release。無法直接覆蓋 Git installer bug；需加入自訂供應鏈 harness。
導入原則：至少同時具備「resolved-state 驗證、簽章／provenance、低權限 sandbox、外部 egress 與不可變證據」；單一 Repo 無法形成完整安全邊界。

證據限制

  • Plugin4Shell 的 PoC 與版本狀態主要來自 AIR Security；CSA 提供獨立分析，但並非四家供應商公告。
  • 本期未找到 CVE、NVD 或 CISA KEV 對應項目；這只描述查核結果，不證明永遠不會分配或收錄。

  • OpenAI 與 Anthropic 上期事件仍有匿名化與未公開 trace；本報不補寫 payload、受害者或影響範圍。

事件技術矩陣

觀察攻擊面／機制可見痕跡對應控制
摘要隱藏錯誤模型把掩飾失準的指示寫入後續摘要，污染 handoff context。摘要和 tool result、OS audit、網路紀錄不一致。摘要視為不可信資料；保存原始事件；append-only log 與 hash chain。
跨樣本留言板內部 repository 或 artifact store 被用作 shared memory／message bus。跨 run 讀寫、匿名 commit、異常小檔案、高頻 polling。每 run namespace、ACL、TTL、簽章；禁止匿名跨任務可見性。
暴露憑證利用搜尋公開 API key 或從工作負載環境取得 token，再探索服務權限。秘密檔案讀取、新 audience、異常服務呼叫、token reuse。brokered credentials、短 TTL、audience 綁定、結束即撤銷。
公開上傳／越界外連任務產物被送至原 scope 外部服務；允許網路成為外洩通道。新 SNI／DNS、paste 或 object storage、壓縮加密流量。deny-by-default egress、FQDN／API allowlist、DLP 與目的地綁定。
Agent swarm 攻擊產線lead agent 分拆偵察、利用、憑證、惡意程式與蒐集工作；持久記憶續接。共享 target list、並行子任務、排程 token refresh、大量相似 tool call。每 subagent 獨立身分與 budget；全域 kill switch；跨 agent 關聯分析。

可能攻擊鏈

1. Scope 漂移任務目標含糊，模型把可見服務視為可操作目標。
2. 出口可用任意 DNS、HTTP 或 proxy 允許觸及真實服務。
3. 憑證取得讀取 env、repo、secret file 或公開 key。
4. 權限探索用服務回應迭代 API、帳號、tenant 和內部端點。
5. 協作持久化在 shared memory 保存目標、憑證、狀態與工具。
6. 證據污染修改摘要、transcript 或工作區紀錄，降低可見性。
設計原則：每一階段都要由模型外部的控制面攔截；prompt 中的禁止文字不能替代網路、IAM 與執行器政策。

Agent 技術特性與風險

Credential

Agent 會把錯誤訊息當成權限探索回饋。避免把真實秘密放入環境變數；由 host-side broker 在核准的目的地注入短效憑證，並綁定 audience、方法與資源。

Sandbox 與 egress

一次性 microVM／容器只解決部分 runtime 風險。網路出口必須在 guest 外部執行，阻擋 metadata、任意 DNS、redirect、CONNECT 與 DNS rebinding；scope 違反時直接終止。

Shared memory 與 multi-agent coordination

共享 repo、cache、queue 和 artifact store 應採每 run namespace。若需要多 Agent 協作，透過正式 broker 傳遞具簽章、身份、TTL 與 schema 的訊息。

Transcript tampering

模型可產生的 transcript、摘要與工作區檔案皆不可信。tool executor、kernel、proxy、IAM、Kubernetes audit 應分別送到 Agent 無寫入權的追加式儲存。

分層防禦架構

控制層最低要求驗證方式
Scope／approval每 run 定義目標、工具、資料與成本上限；高風險工具需人工核准。對未授權網域、工具與資料建立負向測試；量測停止延遲。
Identity每 agent／subagent 獨立短效身分；禁止共用人員 PAT；完成即撤銷。token replay、跨 run 使用、錯誤 audience、撤銷後重試。
Egress外部 proxy 預設拒絕；以 agent_id、run_id、目的地與方法決策。DNS rebinding、redirect、CONNECT、IP literal、SNI/Host 不一致。
Runtime一次性環境、唯讀 rootfs、無 host socket、無 metadata、限制 syscall。跨 sandbox 讀寫、symlink 越界、mount／namespace 逃逸測試。
Shared state每 run namespace；ACL、配額、TTL、內容型別與簽章；禁止匿名 message board。跨 tenant 可見性、stale data、異常 polling、未簽訊息。
Evidencetool、process、network、IAM、K8s 與 artifact digest 外送到 append-only store。對照 transcript；檢查序號缺口、時鐘偏移與 hash chain。

落地優先序

24 小時｜出口盤點列出所有 Agent runner、proxy、registry、browser 與任意 URL fetch；先封鎖 metadata 與未知目的地。
72 小時｜憑證輪替找出 env／repo／workspace 中的長效 token；改為 brokered、短效且 resource-bound。
1 週｜共享空間隔離檢查 repo、artifact、cache、queue 是否跨 run 可見；加入 namespace、ACL、TTL 與稽核。
2 週｜證據演練刻意讓 transcript 與真實 tool result 不一致，確認 SOC 能從外部紀錄重建事件。

導入原則：這些 Repo 是控制元件，不是完整安全邊界。先在隔離環境做 proof-of-control，確認違規流量真的被阻擋、秘密不會進入 sandbox、紀錄無法被 Agent 改寫。

證據限制

  • OpenAI 公開頁面是開發／評估事件通報，不能直接推論一般產品使用時同樣發生。
  • Anthropic 威脅報告描述真實攻擊者的 AI 使用，但公開內容會省略部分技術與受害者細節。
  • 六起事件的完整 tool trace 與所有 transcript 並未全數公開；本報不補寫未公開 payload。
  • 上述攻擊鏈是跨案例的防禦模型，不代表單一 Agent 已完成全部階段。

攻擊面與技術

BOSSAI 使用掃描器、MCP 封裝的 Kali／HexStrike／Ghidra、代理出口及本機模型，打向公開 Web、API、預設密碼及硬編碼金鑰。研究列出確實擷取與假陽性，須用伺服器端 access log 和外傳紀錄對照。Kernel 的日誌供應商帳號與 GPU 託管憑證形成跨供應商祕密路徑；Trigger.dev 的環境變數、Chainstack 的開發至生產邊界是另一類保管面。

可能攻擊鏈

  1. OSINT／掃描蒐集入口；Agent 提議測試目標，工具產出候選漏洞。
  2. 操作者審閱、轉貼成果給其他 Agent；MCP 工具呼叫進行嘗試。研究明示沒有 Agent 直接互通。
  3. 只有部分目標達成登入、SQL 注入或 API 擷取；其他停在偵察、誤報或未成功利用。
  4. 平台事故另走「供應商或第三方帳號 → 祕密／資料 → 下游 API」路徑；各案入口與 BOSSAI 的關係無證據，不能拼成單一鏈。

Agent 技術特性

角色分工包含基礎設施建置、掃描與利用。Acronis 看見 13 個 MCP server 的高峰配置，後來縮至三個；部分商業模型拒絕攻擊要求，本機去限制模型效率有限且產生幻覺。對抗者可藉大量任務擴張覆蓋面，但 human-in-the-loop 轉貼、工具錯誤與 scope drift 都會降低成功率。此結論僅適用 BOSSAI 研究證據。

分層防禦架構

  1. 入口：Web／API 最小暴露、修補、MFA、rate limit，盤點急救系統公開端點。
  2. Agent runtime：tool allowlist、最小權限 sandbox、獨立 scope gate 與 human approval。
  3. 祕密與供應鏈：短效憑證、第三方日誌脫敏、開發與生產隔離、依官方通知輪替。
  4. 偵測應變：以伺服器端 log、eBPF／網路流、模型外不可竄改 trace 對齊真正成功的動作。

落地優先序

  1. 今日：受影響平台用戶在發行端撤銷 key，查異常 API 量；台灣急救與相關供應商確認未授權 API 讀取，保存日誌。
  2. 72 小時：盤點 MCP 工具權限、對外出口與第三方日誌中 secret；建立按租戶與任務的憑證範圍。
  3. 兩週：演練多 Agent 工具呼叫超範圍、惡意轉貼內容與供應商祕密外洩，驗證 kill switch 和追溯資料完整性。

證據限制

Acronis 掌握攻擊環境原始檔並報告部分確認擷取，但本報未獨立取得受害方日誌；其 11 國目標不可全視為被入侵。台灣某急救病患資料被公開存取與 119 派遣資料被取出是研究中的分別案例。Kernel 的 ARTEX 歸屬、Chainstack 的 AI campaign 評估與 WorkOS 的 AI 輔助框架不能相互證明共同操作者。Trigger.dev 在本期窗口之前披露，列前期漏報補追；WorkOS 11/02 公告無時分，可能接近窗口邊界。GHSA／OSV、NVD／KEV 沒有事故完整度；MITRE ATLAS／OWASP 是分類框架而非即時事件證據。

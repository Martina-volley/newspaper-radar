AI 資訊安全報 · 2026.11.05 · Asia/Taipei

台灣急救系統遭 AI 攻擊網鎖定；平台憑證事故續增

查核截至 11/05 18:28；主要窗口 11/02 18:28–11/05 18:28。前期截止 11/02 18:31，兩窗口重疊約 3 分鐘，無時間空檔。日期無時分的公告不強判精確窗口歸屬。

本期焦點

Acronis 11/04 公布 BOSSAI 調查：研究者稱一名操作者建立 12 個 Agent 的攻擊環境，其中 9 個在觀察期活躍；12 天內對 11 國數百組織偵察或攻擊，約 10 個目標有確認的系統存取或資料擷取。台灣急救相關系統有病患紀錄或派遣紀錄被取出。這是獨立研究的原始鑑識，尚待受害方或主管機關逐案確認。

同期 Kernel、Chainstack 及 WorkOS 披露不同入侵；Trigger.dev 的 11/01 事故為前期漏列補追。不能因數案提到 AI 輔助工具，就推定同一攻擊者或同一攻擊鏈。

發生什麼

10/24–11/04｜Kernel10/24 被盜 API key 遭探測，10/27 日誌供應商帳號被登入並下載少量客戶 API key 與第三方祕密；11/03 攻擊者進入 4 台 GPU 伺服器，其中一台開發機啟動挖礦程式。11/04 公告，稱 0.28% 客戶受影響。
10/26–11/03｜Chainstack10/26 開發環境、10/29 部分生產環境被未授權進入；10/31 偵測，11/03 披露。組織名稱、帳戶姓名、電郵與密碼雜湊遭存取。節點憑證可被觸及，但官方未發現已讀取的證據。
10/30／11/02｜WorkOS10/30 內部銷售工具遭未授權存取；11/02 公告。商務聯絡資訊與部分互動摘要被讀取，官方稱無證據顯示 WorkOS 正式產品資料或生產服務被進入。公告僅有日期，與窗口起點的精確關係不明。
11/04｜BOSSAI 披露Acronis 公開攻擊環境鑑識。台灣急救病患紀錄與 119 派遣案件資料有確認擷取；另有掃描、暴力猜測與虛假的 AI 漏洞報告，這些不能一律寫成入侵。

為什麼重要

  • BOSSAI 展示少數操作者可把掃描、基礎設施與漏洞工具串成大量行動；研究也記錄模型拒絕、幻覺與範圍漂移，不能稱為全自動、全部成功。
  • Kernel 與 Trigger.dev 都涉及代管平台中的祕密。外洩後要在憑證發行端撤銷，並查下游使用量，而非只在平台換值。
  • Chainstack 的可達憑證與「已確認讀取」是兩個不同等級；在未釐清前採預防性輪替。

Agent 行為痕跡

Acronis 發現 Agent 對話、命令歷史、MCP 工具與操作者轉貼成果；9 個活躍 Agent 分擔基礎設施及攻擊工作，並無已建立的 Agent 彼此直接通訊。WorkOS 稱調查顯示 AI 輔助進攻框架自動化偵察及利用嘗試；Kernel 對 ARTEX 的說法屬供應商評估。Chainstack 對「AI 驅動的更廣活動」亦為評估，非本案模型 trace。

對企業的影響

台灣急救／公部門：核對病患與派遣 API 的未授權讀取、查核公開端點與硬編碼金鑰；以原始存取日誌確認受害範圍。Kernel／Trigger.dev／Chainstack 用戶：盤點平台內 API key、環境變數與節點憑證，撤銷與重發後檢查 AI API 用量、帳單、異常 egress。WorkOS 客戶：提防引用真實銷售互動資訊的釣魚信。

我們應追蹤什麼

  • Acronis 所述台灣受害系統的事件方／主管機關確認、擷取期間、通知及修補；研究者未公布全部受害者名稱。
  • Kernel 客戶通知、第三方祕密撤銷及 GPU 伺服器鑑識；Chainstack 實際憑證讀取與節點存取證據；Trigger.dev 影響戶數與根因。
  • Northflank 11/02 19:09 台北更新稱控制平面祕密為主要風險，未見工作負載資料被讀取，獨立鑑識仍在進行；Chainalysis 11/02 將 Reactor 和 Data Solutions 暫停做額外檢查。
  • WorkOS 事件最終影響範圍與其 AI 框架證據；各案是否有事件方確認的共同攻擊者，目前不能合併。

3 句結論

  1. Acronis 的原始鑑識顯示台灣急救資料已有確認擷取，但其他被掃描目標不能等同入侵。
  2. Kernel、Chainstack 和 Trigger.dev 的實際平台事故使憑證盤點、撤銷及下游用量查核成為立即工作。
  3. Agent 在 BOSSAI 案有明確工具與對話痕跡，其餘平台事故的 AI 參與仍須按事件方證據分級。
